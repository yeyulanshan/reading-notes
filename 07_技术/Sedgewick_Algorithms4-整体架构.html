第 1.4 节：它把"分析算法"做成了科学方法
这是全书方法论的心脏，也是最值得单独拿出来讲的一节

这一节从一个很朴素的问题开始：

How long will my program take?
Why does my program run out of memory?

然后它的回答方式不是"给你公式"，是把科学方法搬过来：

STEP 1

观察

"Observe some feature of the natural world, generally with precise measurements."

STEP 2

假设

"Hypothesize a model that is consistent with the observations."

STEP 3

预测

"Predict events using the hypothesis."

STEP 4

验证

"Verify the predictions by making further observations."

STEP 5

重复至吻合

"Validate by repeating until the hypothesis and observations agree."

而它给这个类比加了一个硬条件——这一句是整节的关键：

"The experiments we design must be reproducible and the hypotheses that we formulate must be falsifiable."

——实验必须可复现，假设必须可证伪。这就是为什么这一域和其他域不同：在别的域你只能说"这个说法有道理"，在这里你必须说"这个说法能不能被测量推翻"。

它给的具体工具：倍增测试

观察怎么变成数据？靠三个类：

类作用
Stopwatch.java测一段程序的实际运行时间
DoublingTest.java把输入规模每次翻倍，打印各规模下的耗时
DoublingRatio.java同上，但额外输出相邻规模的耗时比值

为什么要输出比值——这是全书最聪明的一个设计。因为如果你测出：

N耗时比值（翻倍后）推断
10000.1 s——
20000.8 s8≈ N³（2³ = 8）
40006.4 s8确认 N³

——翻倍后的比值本身就直接指向增长级：比值≈2 是线性，≈4 是 N²，≈8 是 N³，≈2 且略大于 2 是 N log N。你不需要先知道公式，你能从数据里把公式读出来。

"The total running time of a program is determined by two primary factors: the cost of executing each statement and the frequency of execution of each statement."

—— 1.4 节，数学建模的出发点

从"耗时"到"公式"的四个约定

约定内容为什么需要它
波浪号近似（tilde approximation）写成 g(N) ~ f(N)，意思是 g(N)/f(N) → 1扔掉低阶项——它们让公式变复杂但不改变结论
增长级（order of growth）取 f(N) = N^b log^c N 的形式因为实现算法的结构原件只有几种（语句、条件、循环、嵌套、调用），所以增长级只可能是少数几个函数
代价模型（cost model）明确定义什么是"基本操作"。例如 3-sum 问题的代价模型是"访问数组元素的次数"不谈代价模型就谈复杂度是含糊的
Proposition精确的命题，含增长级与常数例如："The brute-force 3-sum algorithm uses ~ N³/2 array accesses"

注意"代价模型"那一条的严谨性：它不说"3-sum 是 O(N³)"，它说"3-sum 在'数组访问次数'这个代价模型下是 ~N³/2"。换一个代价模型，命题就要重写。这种精确性是这本书的性格。

四种对付"输入依赖"的办法
同一段程序，不同输入耗时可能差几个数量级——这一节讲怎么办
办法内容什么时候用
输入模型"We can carefully model the kind of input to be processed."作者自己标了它的弱点："This approach is challenging because the model may be unrealistic."
最坏情况保证无论什么输入，耗时都小于某个界作者的原话很具体："might be appropriate for the software that runs a nuclear reactor or a pacemaker or the brakes in your car."
随机化算法引入随机性（快排、哈希）。每次运行时间不同，但保证失效的概率比你被闪电击中的概率还低作者对它的评价："Thus, such guarantees are as useful in practice as worst-case guarantees."
摊还分析输入不只是数据，而是客户端操作的序列。摊还分析对操作序列给出最坏情况保证最典型的例子是可扩容数组

摊还分析那两条命题，值得逐字读

实现命题
链表实现的 Bag / Stack / Queue"all operations take constant time in the worst case"
可扩容数组实现的 Bag / Stack / Queue"starting from an empty data structure, any sequence of N operations takes time proportional to N in the worst case (amortized constant time per operation)"

这两条的差别是这一节最重要的东西：

  • 链表的承诺是每一次操作都快（真正的最坏情况常数）
  • 可扩容数组的承诺是平均下来快——某一次扩容操作会慢，但它不常发生

这就是"摊还"这个词的全部意思：不是每次都快，是序列总体快。而这两者能不能互换，取决于你的应用能否容忍偶发的延迟尖峰——这是一个策略问题，不是机制问题。

内存核算：它把"内存"也做成了可计算的
这是很多算法书跳过的部分，而它恰好是通往"真实硬件"那一层的桥

它的方法是：数变量个数，按类型加权字节数。在 64 位机器上：

对象开销含义
对象本身16 字节开销，且总量补齐到 8 的倍数一个空对象也要 16 字节
引用8 字节对象引用就是一个内存地址
嵌套内部类（如链表 Node）额外 8 字节指向外围实例的引用
数组24 字节头部（16 对象开销 + 4 长度 + 4 补齐）Java 里数组是对象
字符串（长度 N）32 + (24 + 2N) = 56 + 2N 字节String 对象 + 字符数组

这里有一个很实用的记账约定，值得单独记：

我们算 String 对象里的 char[] 数组（因为它是创建字符串时分配的），但不算 StackOfStrings 里那些 String 对象（因为它们是客户端创建的）。

——算谁分配的内存，不算谁引用的内存。这条约定让内存核算变得可判定。

🔬 可跑的验证环节 · 这是这一域独有的

这一节的每一条都可以自己验证。而且这是全项目唯一能这样检验自己理解的地方——你说"这段代码是 O(N²)"，跑一下就知道对不对。

  1. 验证倍增比值：自己写一个 O(N²) 和一个 O(N log N) 的函数，用翻倍输入测比值。你应该看到 ≈4 和 ≈2（略大于 2）。如果看到 4 和 2，说明你学会了从数据反推公式。
  2. 验证摊还 vs 最坏：分别用链表和可扩容数组实现栈，压入 10⁶ 个元素。记录每一次操作的耗时并画出来——链表应该是一条平的线；数组应该大部分平、偶发尖峰。这个图就是"摊还"这个词的可视化。
  3. 验证内存核算：用你所用语言的运行时工具（Java 的 -Xmx 试探、Python 的 sys.getsizeof）实测一个 N 元素字符串数组，和上面算出来的 56 + 2N 对一下。误差来自补齐与对齐——那本身就是下一层（硬件）的内容。

第 6 章为什么特殊

前五章都在讲"怎么做"，第 6 章讲"什么时候做不到"。而它把两件事放在一起：

  • 6.5 归约——怎么把一个新问题"化"成一个已知问题
  • 6.6 不可解性——怎么证明一个问题不可能有高效解法（1533 行，全书最长）

这两节合起来给的是工程判断的边界：在动手之前，先判断这个问题该不该找精确解。

——这是这一域最缺的一课。OSTEP 讲的是"怎么把它做对"，图像处理讲的是"怎么把它做好"，而这里讲的是"有些事压根别指望做快"。

这本书不承诺什么
边界一 · 它是 Java 的，而这个项目其他材料偏 C / Python 作者另外有《Algorithms in C》，但那本没有免费在线版。所以要么接受 Java，要么把代码当伪代码读——后者其实完全可行，因为这本书的重点是结构与代价，不是语言细节。
边界二 · 它不碰真实硬件 它给你的复杂度是纸上的。两个都是 O(N) 的遍历，一个用数组一个用链表，在真实机器上可能差 10 倍——因为缓存。这本书不管这件事，这是它必须由 Dive into Systems 补的原因。
边界三 · 它不是参考手册，别当字典用 想查"这个问题的标准解法是什么"，该用 CLRS 或 Skiena。这本书是教进去的，不是查出来的——它的每一节都在讲"为什么是这个结构而不是那个"。
边界四 · 它假设你会写代码 30 节里大量写着"实现这个 API"。不跑代码是学不会这本书的——这和其他域不同。反过来这也是好处：这一域有明确的成败判据。
