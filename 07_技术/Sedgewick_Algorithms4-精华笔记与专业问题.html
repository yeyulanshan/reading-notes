第一部分：精读笔记

一、这本书真正的方法论：四层解剖

它给每个数据结构都按同一套四层讲。这才是它比"算法大全"更值得读的地方——它给你一个可以套用到任何数据结构的检查表：

层问的问题
API · 抽象它对使用者承诺什么？
实现 · 机制数据放在哪、操作怎么做？
性能 · 代价代价多高、在什么条件下成立？
策略 · 选择什么时候用它、什么时候不用？

和 OSTEP 那套"抽象 → 机制 → 策略"是同一个套路，只是多了一层"代价"。而这一层不能省——因为在算法里，代价不是附带信息，它就是选择依据本身。

而第四层不能从第三层直接推出来，这是关键。举一个例子：

红黑树哈希表
查找~2 lg N（保证）~N/M（平均）
有序操作✅ 支持❌ 不支持
最坏情况对数（有保证）线性（无保证）

——如果你的应用需要"找出所有 100 到 200 之间的键"，哈希表的平均代价再低也没用，因为它压根不提供这个操作。

所以选择依据是"你要什么操作"，不是"哪个平均更快"。

二、第 1.4 节：它把"分析算法"做成了科学方法

这是全书方法论的心脏。它从一个朴素的问题开始：

How long will my program take?

Why does my program run out of memory?

然后它的回答方式不是"给你公式"，是把科学方法搬过来：

步内容
1 观察"Observe some feature of the natural world, generally with precise measurements."
2 假设"Hypothesize a model that is consistent with the observations."
3 预测"Predict events using the hypothesis."
4 验证"Verify the predictions by making further observations."
5 重复至吻合"Validate by repeating until the hypothesis and observations agree."

而它给这个类比加了一个硬条件——这一句是整节的关键：

"The experiments we design must be reproducible and the hypotheses that we formulate must be falsifiable."

——实验必须可复现，假设必须可证伪。 这就是为什么这一域和其他域不同：在别的域你只能说"这个说法有道理"，在这里你必须说"这个说法能不能被测量推翻"。

三、倍增测试：从数据里把公式读出来

观察怎么变成数据？靠三个类：

类作用
Stopwatch.java测一段程序的实际运行时间
DoublingTest.java把输入规模每次翻倍，打印各规模下的耗时
DoublingRatio.java同上，但额外输出相邻规模的耗时比值

为什么要输出比值——这是全书最聪明的一个设计。如果耗时 T(N) ~ a·N^b，那么把 N 翻倍：


T(2N) / T(N) ≈ a(2N)^b / (aN^b) = 2^b

——比值只跟指数 b 有关，跟常数 a 无关。 所以你不需要先知道公式，就能从数据里把 b 读出来：

翻倍后的比值增长级例子
1常数数组索引
2线性一次遍历
2（略大于 2）N log N归并排序
4N²选择排序
8N³暴力 3-sum

为什么"略大于 2"就能认出 N log N：因为 2N·log(2N) / (N·log N) = 2·(1 + log2/log N)——当 N 很大时趋近 2，但总是略大于 2。而纯线性的比值恰好是 2，不多不少。

四、从"耗时"到"公式"的四个约定

约定内容为什么需要它
波浪号近似写成 g(N) ~ f(N)，意思是 g(N)/f(N) → 1扔掉低阶项——它们让公式变复杂但不改变结论
增长级取 f(N) = N^b log^c N 的形式因为实现算法的结构原件只有几种（语句、条件、循环、嵌套、调用），所以增长级只可能是少数几个函数
代价模型明确定义什么是"基本操作"不谈代价模型就谈复杂度是含糊的
Proposition精确的命题，含增长级与常数例如：~ N³/2 array accesses

"代价模型"那一条的严谨性值得单独说：它不说"3-sum 是 O(N³)"，它说"3-sum 在'数组访问次数'这个代价模型下是 ~N³/2"。换一个代价模型，命题就要重写。

Proposition（原文）：The brute-force 3-sum algorithm uses ~ N³ / 2 array accesses to compute the number of triples that sum to 0 among N numbers.

五、四种对付"输入依赖"的办法

同一段程序，不同输入耗时可能差几个数量级。这一节讲怎么办：

办法内容什么时候用
输入模型"We can carefully model the kind of input to be processed."作者自己标了弱点："the model may be unrealistic"
最坏情况保证无论什么输入，耗时都小于某个界作者的原话很具体："might be appropriate for the software that runs a nuclear reactor or a pacemaker or the brakes in your car."
随机化算法引入随机性（快排、哈希）"the chance that they are invalid is less than the chance your computer will be struck by lightning"
摊还分析对操作序列给出最坏情况保证最典型的例子是可扩容数组

摊还分析：两条命题值得逐字读

Proposition：In the linked-list implementation of Bag, Stack, and Queue, all operations take constant time in the worst case.

Proposition：In the resizing-array implementation of Bag, Stack, and Queue, starting from an empty data structure, any sequence of N operations takes time proportional to N in the worst case (amortized constant time per operation).

这两条的差别是这一节最重要的东西：

  • 链表的承诺是每一次操作都快（真正的最坏情况常数）
  • 可扩容数组的承诺是平均下来快——某一次扩容操作会慢，但它不常发生

这就是"摊还"这个词的全部意思：不是每次都快，是序列总体快。 而这两者能不能互换，取决于你的应用能否容忍偶发的延迟尖峰——这是一个策略问题，不是机制问题。

一个重要的区分：摊还 vs 平均情况

平均情况分析摊还分析
对什么求平均输入的概率分布操作序列
需要什么假设需要假定输入的分布不需要输入分布假设
保证强度弱——分布不成立就失效强——对任意操作序列都成立
例子BST 查找 ~2 ln N（要求随机键）可扩容数组：任意 N 次操作总共 O(N)

所以摊还是更强的一种保证：它不依赖你对输入的猜测。但它也有软肋——它是对序列的保证，不是对单次操作的保证，所以对"每次操作都有硬实时要求"的场景，摊还不够用。

六、内存核算：它把"内存"也做成了可计算的

这是很多算法书跳过的部分，而它恰好是通往"真实硬件"那一层的桥。方法是：数变量个数，按类型加权字节数。在 64 位机器上：

对象开销
对象本身16 字节开销，且总量补齐到 8 的倍数
引用8 字节
嵌套内部类（如链表 Node）额外 8 字节（指向外围实例的引用）
数组24 字节头部（16 对象开销 + 4 长度 + 4 补齐）
字符串（长度 N）56 + 2N 字节（String 对象 32 + 字符数组 24 + 2N）

而它给了一条很实用的记账约定：

我们算 String 对象里的 char[] 数组（因为它是创建字符串时分配的），但不算 StackOfStrings 里那些 String 对象（因为它们是客户端创建的）。

——算谁分配的内存，不算谁引用的内存。 这条约定让内存核算变得可判定。

七、61 条 Proposition 构成的骨架

全书有 61 条明确标记的结论，分三种类型——这个区分是本书最有价值的设计之一：

类型含义例子能不能依赖
Proposition可证明的数学结论红黑树高度 ≤ 2 lg N✅ 总是（只要前提满足）
Property实际使用中的观察"Quicksort is the fastest general-purpose sort"⚠️ 看环境

绝大多数教材把所有结论写成同一种格式（"定理"或"结论"），而这本书用三种标记明确告诉你每个结论的可信度类型。

以下是各章最该记住的那些：

第 1 章 · 基础

Proposition（链表/数组栈队列）：见上。

Corollary（加权 quick-union）：For weighted quick-union with n sites, the depth of any node is at most lg n.

Proposition（quick-find）：uses one array access for each find() and between N and 2N−1 array accesses for each union().

版本findunion问题

关键在"加权"那一步：不加权时 union 可能把大树挂到小树上。加权指的是总是把小的树挂到大的树上——这样任何一个节点的深度每次增加，它所在的树至少翻倍，所以深度最多 lg N。

第 2 章 · 排序

Proposition：Selection sort uses ~n²/2 compares and n exchanges.

Proposition：Insertion sort uses ~n²/4 compares and ~n²/4 exchanges on average, and ~n²/2 compares and ~n²/2 exchanges in the worst case.

Proposition（归并）：Top-down mergesort uses between 1/2 N lg N and N lg N compares.

Proposition（下界）：No compare-based sorting algorithm can guarantee to sort N items with fewer than lg(N!) ~ N lg N compares.

Proposition：Mergesort is an asymptotically optimal compare-based sorting algorithm.

Proposition（快排最坏）：Quicksort uses ~N²/2 compares in the worst case.

Proposition（三向切分）：Quicksort with 3-way partitioning is entropy-optimal.

下界怎么来的（这是最有价值的部分）：用决策树。N 个元素有 N! 种排列，每次比较只有两个结果，所以一棵高为 h 的决策树最多有 2^h 个叶子。要区分 N! 种情况就需要 2^h ≥ N!，即 h ≥ lg(N!) ~ N lg N。

"熵最优"是什么意思：如果输入里有大量重复键，三向切分把数组分成"小于 / 等于 / 大于"三段，等于段的元素已经就位，不参与递归。于是运行时间与输入的"信息量"成正比——这正是 Shannon 熵的形状。这是 algs4 里唯一一个直接用"熵"命名的结论。

第 2.4 节 · 优先队列

Definition：A binary tree is heap-ordered if the key in each node is larger than (or equal to) the keys in that node's two children (if any).

Definition：A binary heap is a set of nodes with keys arranged in a complete heap-ordered binary tree, represented in level order in an array (not using the first entry).

Proposition：The largest key in a heap-ordered binary tree is found at the root.

Proposition：In an n-item priority queue, the heap algorithms require no more than 1 + lg n compares for insert and no more than 2 lg n compares for remove-the-maximum.

Proposition：Sink-based heap construction is linear time.

Proposition：Heapsort uses fewer than 2 n lg n compares and exchanges.

为什么堆构造是线性时间——直觉上会算成 N log N。关键：从下往上 sink，而不是从上往下 swim。而且节点的高度分布极不均匀：

节点所在层节点数sink 的最大深度
倒数第二层N/41
倒数第三层N/82
根1lg N

——绝大多数节点的 sink 深度极小，只有极少数节点要沉得深。 把 Σ (N/2^(h+1))·h 求和，结果收敛到 2N，是线性的。

而如果用"从上往下 swim"建堆，代价是 N log N。同样的结构，两种构建方向，代价差一个 log。

第 3 章 · 查找（全书主体）

Proposition：Binary search in an ordered array with N keys uses no more than lg N + 1 compares.

Proposition：Inserting a new key into an ordered array uses ~ 2N array accesses in the worst case.

Proposition（BST 命中）：Search hits in a BST built from N random keys require about ~2 ln N compares, on average.

Proposition（BST 有序操作）：Search, insertion, finding the minimum, finding the maximum, floor, ceiling, select, and rank all take time proportional to the height in a BST.

Proposition（2-3 树）：Search and insert operations in a 2-3 tree with N keys are guaranteed to take time proportional to lg N.

Proposition（红黑树高度）：The height of a red-black BST with N nodes is no more than 2 lg N.

Assumption J（均匀散列）：The hash function that we use uniformly distributes keys among the integer values between 0 and M−1.

Proposition（拉链哈希）：In a separate-chaining hash table with M lists and N keys, the number of compares is ~N/M.

Proposition（线性探测）：In a linear-probing hash table of size M with N = αM keys, the number of probes is ~½(1 + 1/(1−α)) for search hits.

五个符号表实现的完整对照：

实现查找（最坏）插入（最坏）有序操作关键前提
无序链表~N~N❌—
有序数组~lg N~2N✅插入要搬移
BST~2 ln N（平均）/ ~N（最坏）同查找✅随机键
红黑树~2 lg N（保证）~2 lg N✅—
哈希表~N/M（平均）/ ~N（最坏）同查找❌均匀散列

红黑树"2 lg N"里的 2 从哪来：红黑树把 2-3 树的每个 3-节点拆成两个节点（一红一黑）。最坏情况下所有链接都是红的，于是高度翻倍。

线性探测那个公式的后果很值得注意：当 α → 1（表快满）时，1/(1−α) → ∞。所以线性探测必须留出空间——实践中 α 通常控制在 1/2 到 1/8 之间。

第 5 章 · 字符串

Property：No prefix-free code uses fewer bits than the optimal prefix-free code. （哈夫曼编码最优性）

这一章的整体逻辑值得单独说——它共享一个思想：不要跟字符"比较"，要利用字符的结构。

节做法

Trie 换来的核心能力是前缀查询：找"所有以 abc 开头的键"只需沿 a→b→c 走三步。哈希表做不到这件事——因为它把键打散了，"前缀"这个概念不存在了。

而哈夫曼编码与 03 域的信息论怎么接：

MacKay（信息论）algs4
问题一个信源最少要用多少比特表示？给定符号频率，怎么构造最短的前缀码？
答案熵 H（下界，且可达）哈夫曼编码（在前缀码这一类里最优）

两者之间有一个必须知道的间隙：哈夫曼编码的期望码长落在 [H, H+1) 之间——它达不到熵，最多逼近。（因为每个符号至少要 1 比特，而概率很小的符号其自信息远小于 1 比特。）MacKay 那边讲的算术编码能突破这个 1 比特的损失。

为什么 6.5 和 6.6 放在一起：因为归约是证明不可解性的工具。你要说明"问题 X 很难"，办法是把 X 归约到一个已知很难的问题。

书里给出的那个 Theorem 很能说明这一节的气质：

Theorem：Given a purported theorem (such as one for the Riemann Hypothesis), can you prove it is true using at most n symbols in some formal system such as Zermelo-Fraenkel set theory?

——它把"证明一个数学定理"本身当成一个计算问题。 这一节讨论的不是"怎么写代码"，是"计算这件事本身的边界"。

B 树为什么放在"语境"章而不是"查找"章——因为它优化的目标不是"比较次数"，是"磁盘访问次数"：

红黑树B 树
优化目标比较次数I/O 次数（页读取）
节点大小1 个键一整页（几百到几千个键）

——如果每次节点访问都是一次磁盘 I/O（毫秒级），那么 60 次和 3 次的差别是几秒 vs 几毫秒。把它放进"查找"章会和红黑树比"谁的比较次数少"，那就完全问错了问题。

第二部分：20个专业问题（附通俗解释）

1. 这本书用哪四层解剖每一个数据结构？为什么第四层不能从第三层推出来？

专业回答

四层：API（抽象）· 实现（机制）· 性能（代价）· 策略（选择）。

第四层不能从第三层直接推出的理由——两个结构的平均代价可能一样，但假设与能力完全不同：

红黑树哈希表
查找~2 lg N（保证）~N/M（平均，依赖均匀散列）
有序操作✅❌
最坏情况对数（有保证）线性（无保证）

如果你的应用需要"找出所有 100 到 200 之间的键"，哈希表的平均代价再低也没用——它压根不提供这个操作。 所以选择依据是"你要什么操作"，不是"哪个平均更快"。

📌 通俗解释

四层的顺序不能颠倒：先问"我需要什么能力"，再问"哪个实现能做到"，最后才是选。先看性能表再选结构的人，常常选到一个做不到他要的事的结构。

2. 什么是"代价模型"？为什么书里不说"3-sum 是 O(N³)"？

专业回答

代价模型（cost model）的定义是明确定义什么是"基本操作"。3-sum 的代价模型是访问数组元素的次数（读或写都算）。

"O(N³)"代价模型 + Proposition
说的是什么一个上界，忽略常数确切的操作次数（含常数）
在什么衡量下通常指"时间"，但没说是哪种明确：数组访问次数

Proposition：The brute-force 3-sum algorithm uses ~ N³ / 2 array accesses.

换个代价模型，命题就要重写。

📌 通俗解释

"快"这个字必须配一个衡量标准。说"这个算法访问了 N³/2 次数组"是精确的；说"它是 O(N³)"是模糊的。 而模糊的说法无法用来比较两个实现。

3. 加倍测试的比值为什么能直接读出增长级？

专业回答

若 T(N) ~ a·N^b，则 T(2N)/T(N) ≈ 2^b——比值只跟指数有关，跟常数无关。

比值增长级
1常数
2线性
2（略大于 2）N log N
4N²

"略大于 2"就是 N log N 的来源：2N·log(2N)/(N·log N) = 2(1 + log2/log N)，趋近 2 但总略大。

📌 通俗解释

你不需要先知道公式，能从数据里把公式读出来。 这是这一域最有用的一个技能——它让你在不知道理论的情况下也能判断一个程序大概多快。

4. 什么是"摊还"？它和"平均情况"有什么区别？

专业回答

Proposition（链表）：all operations take constant time in the worst case.

Proposition（可扩容数组）：starting from an empty data structure, any sequence of N operations takes time proportional to N (amortized constant time per operation).

平均情况分析摊还分析
对什么求平均输入的概率分布操作序列
需要假设需要假定输入分布不需要
保证强度弱（分布不成立就失效）强（对任意序列成立）
例子BST 查找 ~2 ln N（要求随机键）可扩容数组

摊还更强，但它是对序列的保证，不是对单次操作的保证。

📌 通俗解释

可扩容数组的意思是"总共很快"，不是"每一次都快"——某一次扩容会慢几百倍。如果用户能感受到那一次卡顿（音视频、交互界面），摊还保证就不够用。

5. 归并排序的比较次数是多少？为什么它是最优的？

专业回答

Proposition：Top-down mergesort uses between 1/2 N lg N and N lg N compares.

Proposition（下界）：No compare-based sorting algorithm can guarantee to sort N items with fewer than lg(N!) ~ N lg N compares.

Proposition：Mergesort is an asymptotically optimal compare-based sorting algorithm.

下界的来源（决策树）：N 个元素有 N! 种排列 → 每次比较两个结果 → 高为 h 的树最多 2^h 个叶子 → 2^h ≥ N! → h ≥ lg(N!) ~ N lg N。

"渐近最优"的依据：上界 ~N lg N 与下界 ~N lg N 撞上了。

📌 通俗解释

归并排序在所有"靠比较来排序"的算法里已经到顶了。但注意"靠比较"这个限制——基数排序不比较，它能突破这个下界。

6. 快速排序的最坏情况是什么？"熵最优"是什么意思？

专业回答

Proposition：Quicksort uses ~N²/2 compares in the worst case.

最坏情况：每次切分都极不均衡。这发生在输入已有序且每次取第一个元素当切分点时。

随机化的价值（书里的原话）："the chance that they are invalid is less than the chance your computer will be struck by lightning."

Proposition（三向切分）：Quicksort with 3-way partitioning is entropy-optimal.

"熵最优"：三向切分把数组分成"小于/等于/大于"三段，等于段已就位、不参与递归。于是运行时间与输入的"信息量"成正比——这正是 Shannon 熵的形状。

📌 通俗解释

随机化没有消除最坏情况，只是让它变得极其不可能。对核反应堆、起搏器这类场景，这个区别是致命的——书里就是拿这几个例子来对照"最坏情况保证"的用途的。

7. 优先队列的堆操作代价是多少？为什么建堆是线性的？

专业回答

Proposition：In an n-item priority queue, the heap algorithms require no more than 1 + lg n compares for insert and no more than 2 lg n compares for remove-the-maximum.

Proposition：Sink-based heap construction is linear time.

Proposition：Heapsort uses fewer than 2 n lg n compares and exchanges.

为什么建堆线性——关键：从下往上 sink，而不是从上往下 swim。节点的高度分布极不均匀：

层节点数sink 深度
倒数第二N/41
倒数第三N/82
根1lg N

Σ (N/2^(h+1))·h 收敛到 2N。而"从上往下 swim"建堆是 N log N——同样的结构，两种方向，差一个 log。

📌 通俗解释

直觉会说"每个操作 O(log N)，建 N 个就是 N log N"。错在把"最坏的那个操作"乘了 N 次，而实际上最坏的操作只占极少数。

8. 二叉堆的两个定义里，哪两个设计要点值得注意？

专业回答

Definition：A binary tree is heap-ordered if the key in each node is larger than (or equal to) the keys in that node's two children.

Definition：A binary heap is a set of nodes with keys arranged in a complete heap-ordered binary tree, represented in level order in an array (not using the first entry).

两个要点：

① 完全不使用指针——用数组下标运算代替（k 的子节点是 2k 和 2k+1）；

② 不用第 0 项，这样下标运算更简洁。

📌 通俗解释

数组下标是算术，指针是跳转。前者在真实机器上快得多（这是我们后面要讲的"内存层级"的伏笔）。

9. 并查集从 quick-find 到加权 quick-union，代价怎么降下来的？

专业回答

版本findunion
quick-find1N ~ 2N−1
quick-union~N（最坏）取决于树高
加权 quick-union~lg N~lg N

Corollary：For weighted quick-union with n sites, the depth of any node is at most lg n.

"加权"的论证很漂亮：总是把小的树挂到大的树上 → 任何一个节点的深度每次增加，它所在的树至少翻倍 → 深度最多 lg N。它不追踪树的形状，只追踪"深度增加一次意味着树翻倍"。

📌 通俗解释

不加权时，union 可能把大树挂到小树上，树越来越高。加权就是"小的听大的"，一句话的规则，把 O(N) 变成 O(log N)。

10. 二叉搜索树的平均代价为什么不等于最坏代价？

专业回答

Proposition：Search hits in a BST built from N random keys require about ~2 ln N compares, on average.

注意 2 ln N ≈ 1.39 lg N——比二分查找的 lg N 还差一点，但 BST 提供了二分查找没有的能力：动态插入。

而"随机键"这个前提是关键：如果键是有序插入的，树退化成链表，高度变成 N。

📌 通俗解释

"平均 O(log N)"这个说法必须跟着"输入是随机的"这个前提。而真实数据里"有序"很常见（时间戳、自增 ID）——这是最经典的一类事故：测试用随机数据全过，上线遇到有序数据就挂。

11. 红黑树的"2 lg N"是怎么保证的？它付出了什么？

专业回答

Proposition（2-3 树）：Search and insert in a 2-3 tree with N keys are guaranteed to take time proportional to lg N.

Proposition（红黑树）：The height of a red-black BST with N nodes is no more than 2 lg N.

"2"从哪来：红黑树把 2-3 树的每个 3-节点拆成两个节点（一红一黑）。最坏情况下所有链接都是红的，高度翻倍。

付出的代价：① 实现复杂度（旋转与颜色翻转，边界情况多）；② 常数因子（2 lg N 比 BST 的 1.39 lg N 还大）；③ 每节点多一个颜色位。

📌 通俗解释

红黑树买的是保险，不是速度。在随机数据上，未平衡的 BST 反而更快。 它的价值是"输入有序时也不会退化"。

12. 哈希表的两条命题说了什么？"均匀散列"是假设还是结论？

专业回答

Assumption J：The hash function that we use uniformly distributes keys between 0 and M−1.

Proposition（拉链）：the number of compares is ~N/M.

Proposition（线性探测）：with N = αM keys, the number of probes is ~½(1 + 1/(1−α)) for search hits.

注意它叫 Assumption，不叫 Proposition。 所以——哈希表的 O(1) 从来不是被证明的，它是在一个假设下推导的。

线性探测那个公式的后果：当 α → 1 时 1/(1−α) → ∞。所以线性探测必须留出空间，实践中 α 通常控制在 1/2 到 1/8。

📌 通俗解释

哈希表"很快"这件事依赖一个可能不成立的前提。而对手可以故意构造让所有键碰撞的输入——这就是哈希碰撞攻击，真实发生过，导致过某些 web 框架的 DoS 漏洞。所以现代实现会在散列里加随机种子。

13. 五个符号表实现里，哪个不支持有序操作？为什么？

专业回答

哈希表。因为键被散列函数打散了——"顺序"这个概念在它里面不存在。

这不实现上的疏忽，是根本的代价。书里的命题明确说 floor / ceiling / rank / select 这些操作"take time proportional to the height in a BST"——它们压根没有哈希表的版本。

📌 通俗解释

这是API 层面的错误，不是性能问题。如果你的应用需要范围查询，哈希表再快也做不到——这不是"把哈希表优化一下"能解决的。

14. 图算法为什么必须同时用 V 和 E 表示复杂度？

专业回答

Proposition：DFS marks all the vertices connected to a given source in time proportional to the sum of their degrees.

Proposition：DFS uses preprocessing time and space proportional to V + E.

"预处理"的含义：先花 O(V+E) 走一遍、建好辅助数组，之后每次查询只需常数时间。

为什么必须写 V+E：稠密图 E ~ V²，稀疏图 E ~ V，同一算法的实际代价差一个数量级。

最常见的坑：用邻接矩阵实现 DFS → 遍历变成 O(V²)，即使图是稀疏的。

📌 通俗解释

图的"大小"要用两个数描述。说"这个图算法是线性"时必须说清是对 V 线性还是对 E 线性。

15. MST 和最短路径的命题，前提的强弱对比说明什么？

专业回答

算法前提代价
Prim / Kruskal任意连通带权图（无额外前提）E log V
Dijkstra非负权E log V
拓扑序最短路DAGE + V
Bellman-Ford无负环（最弱）E·V

MST 的两条命题都强调"任意连通带权图"——这是它们比最短路更强的地方。而最短路的前提越弱，代价越高。

📌 通俗解释

这张表本身就是答案：你能接受的前提越少，算法就越慢。 而"负权"这个前提在"距离""成本"这类语义里看起来完全合理，所以把 Dijkstra 用在有负权的图上是极常见的实现错误——程序不报错，只是偶尔给出偏大的答案。

16. "渐近最优"这个说法为什么必须跟着"在哪一类算法里"？

专业回答

Proposition：Mergesort is an asymptotically optimal compare-based sorting algorithm.

注意 "compare-based" 不能去掉。 基数排序不比较，它把键看成字符序列逐位分桶，所以不受 lg(N!) ~ N lg N 下界的约束。

归并排序基数排序
代价模型比较次数字符访问次数
代价~N lg N~W·N（W = 键长）
下界撞到下界（在比较模型里）不受那个下界约束

"最优"永远要问两个问题：① 在哪个代价模型下？② 在哪一类算法里？

📌 通俗解释

算法领域几乎每一个"最优"都带一个隐含的模型假设。这和 03 域 MacKay 讲的"定理的前提"是同一条纪律：结论必须和前提一起引用。

17. 为什么 B 树放在"语境"章而不是"查找"章？

专业回答

因为 B 树优化的目标不是"比较次数"，是"磁盘访问次数"。

红黑树B 树
节点大小1 个键一整页
高度（N=10⁹）约 60约 3

如果每次节点访问是一次磁盘 I/O（毫秒级），60 次 vs 3 次是几秒 vs 几毫秒。

所以 B 树不是"更快的查找结构"，它是"针对另一种硬件层级重新设计的结构"。 把它放进"查找"章会和红黑树比"谁的比较次数少"，那就完全问错了问题。

它和 OSTEP 的接口：文件系统的索引就是 B 树。

📌 通俗解释

换一个硬件层级，最好的数据结构就变了。 内存里的王者（红黑树）到了磁盘上就不合适了。

18. Trie 换来了什么？字符串问题为什么需要专门的结构？

专业回答

因为字符串有一个哈希表不利用的性质：共享前缀。

哈希表Trie
前缀查询❌✅ 天然支持
有序遍历❌✅
空间取决于 α取决于前缀共享程度

Trie 换来的核心能力是前缀查询：找"所有以 abc 开头的键"只需沿 a→b→c 走三步。哈希表做不到——它把键打散了，"前缀"不存在了。

这解释了为什么自动补全、拼写检查、IP 路由表都用 Trie。

📌 通俗解释

不同的数据有不同结构可以利用。 哈希表把所有数据都当成"一个键"，而字符串其实是一串字符——Trie 利用了这个被浪费掉的结构。

19. 哈夫曼编码的"最优"是什么意思？它和 03 域的信息论怎么接？

专业回答

Property：No prefix-free code uses fewer bits than the optimal prefix-free code.

MacKay（信息论）algs4
问题一个信源最少要多少比特？给定频率，怎么构造最短前缀码？
答案熵 H（下界，可达）哈夫曼编码（前缀码里最优）
关系理论上界一类实用编码里的最优解

两者之间有一个必须知道的间隙：哈夫曼的期望码长落在 [H, H+1)——它达不到熵，最多逼近。（每个符号至少 1 比特，而小概率符号的自信息远小于 1 比特。）MacKay 讲的算术编码能突破这个 1 比特的损失。

📌 通俗解释

"哈夫曼是最优的"是在"前缀码"这一类里的最优，而前缀码整体达不到熵。这是跨域引用时最容易出的错：把"A 领域里的最优"当成"A 领域的极限"。

20. 读完这两本书（algs4 + Dive into Systems），你应该能回答哪三类问题？

专业回答

第一类 · 预测——"这段代码大概多快？"

量出增长级（倍增比值）· 说出代价模型 · 指出命题的前提（随机键？非负权？单线程？）

第二类 · 选择——"这个需求该用什么结构？"

先问 API 再问代价 · 知道哈希表不支持有序操作 · 知道 B 树和红黑树是针对不同硬件层级的 · 知道小 N 看常数、大 N 看增长级

第三类 · 判断边界——"这个问题值不值得继续优化？"

认出下界 · 认出 NP 完全与不可判定 · 知道该换目标（近似、随机、限制规模）而不是继续压常数

而这三类问题的共同基础是书里那句方法论：

"The experiments we design must be reproducible and the hypotheses that we formulate must be falsifiable."

📌 通俗解释

这一句可以当整个 07 域的方法论座右铭。 它把这一域和别的域区分开了：在别的域你只能说"这个说法有道理"，在这里你必须说"这个说法能不能被测量推翻"。
