第一部分：精读笔记

一、先说清楚：什么叫"计算基础"

07 域原本只有系统（OSTEP）与图像（冈萨雷斯）。缺的"计算基础"其实是四层不同的东西：

层内容由谁覆盖
① 算法怎么把问题变成可计算的步骤algs4
② 数据结构数据怎么组织，决定哪些操作便宜algs4
③ 真实硬件上的性能缓存、内存层级、访问模式Dive into Systems
④ 不可解性有些问题没有高效解法algs4 第 6 章

③ 是最容易被漏掉的一层，而它恰好是这一域最该讲的——因为这一域的特色是"能亲手验证"。算法复杂度是纸上的，缓存行为是跑出来的。

二、algs4 的核心方法论：四层解剖

它给每个数据结构都按同一套四层讲。这是它比"算法大全"更值得读的地方——它给你一个可以套用到任何数据结构的检查表：

层问的问题
API · 抽象它对使用者承诺什么？
实现 · 机制数据放在哪、操作怎么做？
性能 · 代价代价多高、在什么条件下成立？
策略 · 选择什么时候用它、什么时候不用？

和 OSTEP 那套"抽象 → 机制 → 策略"是同一个套路，只是多了一层"代价"。而这一层不能省——在算法里，代价不是附带信息，它就是选择依据本身。

而第四层不能从第三层直接推出来：两个结构的平均代价可能一样，但假设与能力完全不同。

红黑树哈希表
查找~2 lg N（保证）~N/M（平均，依赖均匀散列）
有序操作✅ 支持❌ 不支持
最坏情况对数（有保证）线性（无保证）

——如果你需要"找出所有 100 到 200 之间的键"，哈希表的平均代价再低也没用，因为它压根不提供这个操作。

三、algs4 第 1.4 节：把"分析算法"做成科学方法

这一节从一个朴素的问题开始：

How long will my program take?

Why does my program run out of memory?

然后它把科学方法搬过来：

步内容
1 观察"Observe some feature of the natural world, generally with precise measurements."
2 假设"Hypothesize a model that is consistent with the observations."
3 预测"Predict events using the hypothesis."
4 验证"Verify the predictions by making further observations."
5 重复至吻合"Validate by repeating until the hypothesis and observations agree."

而它给这个类比加了一个硬条件——这一句是整节的关键：

"The experiments we design must be reproducible and the hypotheses that we formulate must be falsifiable."

——实验必须可复现，假设必须可证伪。 这就是为什么这一域和其他域不同：在别的域你只能说"这个说法有道理"，在这里你必须说"这个说法能不能被测量推翻"。

具体工具：倍增测试

类作用
Stopwatch.java测运行时间
DoublingTest.java输入规模每次翻倍，打印耗时
DoublingRatio.java额外输出相邻规模的耗时比值

为什么要输出比值——这是最聪明的一个设计。若 T(N) ~ a·N^b，那么把 N 翻倍：


T(2N) / T(N) ≈ a(2N)^b / (aN^b) = 2^b

——比值只跟指数 b 有关，跟常数 a 无关。 所以你不需要先知道公式，就能从数据里把 b 读出来：

翻倍后的比值增长级例子
1常数数组索引
2线性一次遍历
2（略大于 2）N log N归并排序
4N²选择排序
8N³暴力 3-sum

"略大于 2"就是 N log N：因为 2N·log(2N)/(N·log N) = 2(1 + log2/log N)，趋近 2 但总略大。而纯线性的比值恰好是 2，不多不少。

四个约定：从"耗时"到"公式"

约定内容为什么需要
波浪号近似g(N) ~ f(N) 意思是 g(N)/f(N) → 1扔掉低阶项
增长级取 f(N) = N^b log^c N 的形式算法的结构原件只有几种，所以增长级只可能是少数几个函数
代价模型明确定义什么是"基本操作"不谈代价模型就谈复杂度是含糊的
Proposition精确的命题，含增长级与常数例：~ N³/2 array accesses

"代价模型"这一条的严谨性值得单独说：它不说"3-sum 是 O(N³)"，它说"3-sum 在'数组访问次数'这个代价模型下是 ~N³/2"。

Proposition：The brute-force 3-sum algorithm uses ~ N³ / 2 array accesses.

换一个代价模型，命题就要重写。

四、四种对付"输入依赖"的办法

办法内容什么时候用
输入模型carefully model the kind of input作者自己标了弱点："the model may be unrealistic"
最坏情况保证无论什么输入都小于某个界作者的例子很具体："nuclear reactor or a pacemaker or the brakes in your car"
随机化算法引入随机性（快排、哈希）"the chance that they are invalid is less than the chance your computer will be struck by lightning"
摊还分析对操作序列给出保证可扩容数组

摊还 vs 平均情况（这个区分很重要）

平均情况分析摊还分析
对什么求平均输入的概率分布操作序列
需要什么假设需要假定输入分布不需要

例子BST 查找 ~2 ln N（要求随机键）可扩容数组：任意 N 次操作总共 O(N)

摊还是更强的一种保证（不依赖对输入的猜测），但它是对序列的保证，不是对单次操作的保证——所以对"每次操作都有硬实时要求"的场景，摊还不够用。

五、61 条 Proposition：三种可信度标记

这是本书最有价值的设计之一。 绝大多数教材把所有结论写成同一种格式，而这本书用三种标记明确告诉你每个结论的可信度类型：

类型含义例子能不能依赖
Proposition可证明的数学结论红黑树高度 ≤ 2 lg N✅ 总是（只要前提满足）
Property实际使用中的观察"Quicksort is the fastest general-purpose sort"⚠️ 看环境
Assumption无法证明的前置假定均匀散列假设❌ 可能不成立

各章最该记住的那些

第 1 章 · 基础

Corollary（加权 quick-union）：the depth of any node is at most lg n.

Proposition（quick-find）：between N and 2N−1 array accesses for each union().

并查集四版本：quick-find（find 1 / union N）→ quick-union（最坏 ~N）→ 加权（~lg N）→ +路径压缩（接近常数）。

"加权"的论证很漂亮：总是把小的树挂到大的树上 → 任何一个节点的深度每次增加，它所在的树至少翻倍 → 深度最多 lg N。它不追踪树的形状，只追踪"深度增加一次意味着树翻倍"。

第 2 章 · 排序

Proposition（归并）：uses between 1/2 N lg N and N lg N compares.

Proposition（下界）：No compare-based sorting algorithm can guarantee to sort N items with fewer than lg(N!) ~ N lg N compares.

Proposition：Mergesort is an asymptotically optimal compare-based sorting algorithm.

Proposition（快排最坏）：Quicksort uses ~N²/2 compares in the worst case.

Proposition（三向切分）：Quicksort with 3-way partitioning is entropy-optimal.

下界的来源（决策树）：N! 种排列 → 每次比较两个结果 → 2^h ≥ N! → h ≥ lg(N!) ~ N lg N。

"熵最优"：三向切分把数组分成"小于/等于/大于"，等于段已就位、不参与递归。运行时间与输入的信息量成正比——这正是 Shannon 熵的形状。

第 2.4 节 · 优先队列

Proposition：no more than 1 + lg n compares for insert, 2 lg n for remove-the-maximum.

Proposition：Sink-based heap construction is linear time.

Proposition：Heapsort uses fewer than 2 n lg n compares and exchanges.

为什么建堆线性：从下往上 sink，而节点高度分布极不均匀——倒数第二层有 N/4 个节点但只需沉 1 层，根只有 1 个但要沉 lg N 层。Σ (N/2^(h+1))·h 收敛到 2N。而"从上往下 swim"是 N log N——同样的结构，两种方向，差一个 log。

第 3 章 · 查找（全书主体）

Proposition：Binary search in an ordered array uses no more than lg N + 1 compares.

Proposition：Inserting a new key into an ordered array uses ~ 2N array accesses.

Proposition（BST）：Search hits in a BST built from N random keys require about ~2 ln N compares.

Proposition（BST 有序操作）：search, insert, min, max, floor, ceiling, select, rank all take time proportional to the height.

Proposition（红黑树）：The height of a red-black BST with N nodes is no more than 2 lg N.

Assumption J：the hash function uniformly distributes keys.

Proposition（拉链）：the number of compares is ~N/M.

Proposition（线性探测）：with N = αM keys, probes is ~½(1 + 1/(1−α)) for search hits.

五个符号表实现的完整对照：

实现查找（最坏）插入（最坏）有序操作关键前提
无序链表~N~N❌—
有序数组~lg N~2N✅插入要搬移
BST~2 ln N（平均）/ ~N（最坏）同查找✅随机键
红黑树~2 lg N（保证）~2 lg N✅—
哈希表~N/M（平均）/ ~N（最坏）同查找❌均匀散列

红黑树的"2"从哪来：它把 2-3 树的 3-节点拆成两个节点（一红一黑），最坏情况下所有链接都是红的，高度翻倍。

线性探测的 α 效应：α → 1 时 1/(1−α) → ∞。代价不是线性上升，是急剧上升。 实践中 α 通常控制在 1/2 到 1/8 之间。

第 4 章 · 图

Proposition（DFS）：uses preprocessing time and space proportional to V + E.

Proposition（Prim / Kruskal）：computes the MST of any connected edge-weighted graph.

Proposition（Dijkstra）：edge-weighted digraphs with nonnegative weights.

Proposition（拓扑序）：in time proportional to E + V for edge-weighted DAGs.

Proposition（Bellman-Ford）：edge-weighted digraphs with no negative cycles.

这一组最有价值的是前提的强弱对比：

算法前提代价
Dijkstra非负权（最强）E log V
拓扑序DAGE + V
Bellman-Ford无负环（最弱）E·V

——前提越弱，代价越高。

为什么 6.5 和 6.6 放在一起：归约是证明不可解性的工具——要说明"问题 X 很难"，办法是把它归约到一个已知很难的问题。

——它把"证明一个数学定理"本身当成一个计算问题。

六、Dive into Systems：性能的另一半

记忆层级

层速度容量类比
CPU 寄存器最快最小—
CPU 缓存快小书桌（3 本）
主存慢大门外书架
磁盘最慢最大校园图书馆

为什么必须存在：快的做不大，大的做不快——这是物理与成本的双重约束，不是设计上的妥协。

两种局部性，两个不同的问题

类型含义决定缓存的什么
时间局部性刚用过的东西很可能马上再用淘汰策略（留谁）
空间局部性用了某个地址，附近地址很可能也要用块大小（搬多少）

而这一层设计只有一个依据：

"systems look to the past as a predictor of what will likely happen in the future."

——用过去预测未来。 为什么只能靠过去？书里说得直接：<em>"hardware designers haven't discovered how to build circuits that can predict the future."</em>

那个 5 倍的例子

全书最重要的一个例子：N×N 矩阵求平均，两个版本唯一的差别是内存索引方式：

版本 1（快约 5 倍）版本 2
total += mat[i][j];total += mat[j][i];

书里的解释：

<strong>版本 1</strong>："accesses the matrix's values sequentially in memory… it pays the cost of going to memory only once for every block of values."

<strong>版本 2</strong>："accesses the matrix's values by repeatedly jumping between rows across nonsequential memory addresses. It never reads from the same cache block in subsequent memory accesses… Thus, it pays the cost of going to memory for every matrix value it reads."

关键在于 C 的二维数组是行优先存储的——mat[i][0]、mat[i][1]、mat[i][2] 在内存里连续。

而最关键的一点是：两个版本的工作量完全一样——都是 N² 次加法、N² 次数组访问。在 algs4 的代价模型下，它们是一样快的。

缓存设计

地址分三段：

段决定什么
标签（tag）这个位置里是不是我要的那块
索引（index）放到哪一组
块内偏移（offset）在块内哪个字节

三种映射的取舍：

设计块能放哪冲突硬件复杂度
直接映射唯一一个位置高最低
组相联（N 路）组内 N 个位置任选中中
全相联任何位置最低最高

取舍的本质：灵活性换硬件复杂度。而路数不能无限加——判断命中的时间会拉长，而缓存的全部价值就在于"快"。

两种写策略：

策略做法代价
写回只改缓存、标脏；淘汰时才写回内存写少；多核下一致性更复杂
写直达每次都同时写缓存和内存内存写多；但简单、一致性好

可以测量的

工具量什么
cachegrind（11.5）缓存缺失次数（按 L1/L2/L3 分别统计）
massif（12.3.3）峰值内存占用 + 时间曲线

这两个工具合起来，把"内存"从一个模糊概念变成两个可量化的数。

而这一点与 algs4 的方法论是同一条纪律：<em>"The experiments we design must be reproducible and the hypotheses that we formulate must be falsifiable."</em> ——这一层同样遵守它。你不需要"相信"局部性理论，你可以测。

代码优化（第 12 章）

手法做法利用什么
循环交换交换嵌套循环顺序，让最内层访问连续内存空间局部性（就是那个 5 倍）
循环分裂一个循环拆成多个让工作集更小
循环合并多个循环合成一个减少重复遍历

特别注意"循环交换"的三条限制：① 循环体不能有跨迭代依赖；② 别名问题让编译器无法证明安全；③ 数据能装进缓存时收益消失。

七、一个漂亮的跨书连接：LRU 在两个层面上

我核对了两本书的原文（这不是联想）：

OSTEP（操作系统）Dive into Systems
问题物理内存满了，换出哪一页？缓存满了，淘汰哪一块？
答案LRU 及其近似LRU
为什么用过去预测未来同一句话

这个连接的价值：<em>同一个策略在从寄存器到磁盘的每一层都被使用。</em>而两本书从两端逼近它——一本从软件策略，一本从硬件机制。

而它正好印证了"抽象→机制→策略"：在缓存层，机制和策略都由硬件定死（软件改不了）；在虚拟内存层，两者都在操作系统手里（可调）。同一件事在不同层级的可调整程度不同——这本身就是一个重要的认知。

注意一个限定：精确 LRU 在硬件里也是近似的（维护访问顺序代价太高）。OSTEP 里也讲了同样的道理：精确 LRU 在软件里也难实现。

八、多核：第三类代价

algs4 的全部结论都假设单线程。 多核引入三类它不管的代价：

代价机制
同步开销加锁、解锁、等待。锁的争用随核数增加而恶化
缓存一致性流量一个核写了共享数据，其他核的副本要失效——大量跨核通信
伪共享（false sharing）两个核改的是不同的变量，但它们落在同一个缓存块里 → 系统仍要来回同步这个块

伪共享最反直觉：两个线程操作两个独立变量，逻辑上毫无关系，但因为它们在内存里挨着，性能可能比单线程还差。

这直接解释了为什么"数组比链表快"在多线程下可能反转——数组的密集布局在单线程时是优点，在多线程下可能变成伪共享的来源。

2. 这本书用哪四层解剖数据结构？为什么第四层不能从第三层推出来？

专业回答

API（抽象）· 实现（机制）· 性能（代价）· 策略（选择）。

第四层不能从第三层推出的理由——两个结构的平均代价可能一样，但假设与能力完全不同。例：哈希表平均 ~N/M（比红黑树的 2 lg N 好），但它不支持有序操作。

📌 通俗解释

四层的顺序不能颠倒：先问"我需要什么能力"，再问"哪个实现能做到"，最后才是选。先看性能表再选结构的人，常常选到一个做不到他要的事的结构。

换个代价模型，命题就要重写。

📌 通俗解释

"快"这个字必须配一个衡量标准。 而模糊的说法无法用来比较两个实现。

4. 加倍测试的比值为什么能直接读出增长级？

专业回答

若 T(N) ~ a·N^b，则 T(2N)/T(N) ≈ 2^b——比值只跟指数有关，跟常数无关。

比值增长级
1常数
2线性
2（略大于 2）N log N
4N²
8N³

📌 通俗解释

你不需要先知道公式，能从数据里把公式读出来。 这是这一域最有用的一个技能。

5. 什么是"摊还"？它和"平均情况"有什么区别？

专业回答

平均情况摊还
对什么求平均输入的概率分布操作序列
需要假设需要假定输入分布不需要
保证强度弱强
例子BST 查找（要求随机键）可扩容数组

摊还更强，但它是对序列的保证，不是对单次操作的保证。

📌 通俗解释

可扩容数组的意思是"总共很快"，不是"每一次都快"——某一次扩容会慢几百倍。如果用户能感受到那次卡顿，摊还就不够用。

6. Proposition、Property、Assumption 三者的区别为什么重要？

专业回答

类型含义例能不能依赖
Proposition可证明的数学结论红黑树高度 ≤ 2 lg N✅ 总是（前提满足时）
Property实际使用中的观察"Quicksort is the fastest general-purpose sort"⚠️ 看环境
Assumption无法证明的前置假定均匀散列假设❌ 可能不成立

混淆的后果：

① 把 Assumption 当 Proposition → 以为哈希表有 O(1) 的保证（而它依赖一个可被破坏的假定——这就是哈希碰撞攻击）

② 把 Property 当 Proposition → 以为"快排总是最快"

③ 忘掉 Proposition 的前提 → 在有序数据上遇到 BST 退化成 O(N)

📌 通俗解释

绝大多数教材把所有结论写成同一种格式，而这本书用三种标记明确告诉你每个结论的可信度类型。<em>这和我们在 08 域为米勒做的 A/B/C 分级是同一个思路。</em>

7. 归并排序的比较次数是多少？为什么它是最优的？

专业回答

Proposition：uses between 1/2 N lg N and N lg N compares.

Proposition（下界）：No compare-based sorting algorithm can guarantee to sort N items with fewer than lg(N!) ~ N lg N compares.

Proposition：Mergesort is an asymptotically optimal compare-based sorting algorithm.

下界的来源（决策树）：N! 种排列 → 每次比较两个结果 → 2^h ≥ N! → h ≥ lg(N!) ~ N lg N。

📌 通俗解释

归并排序在"靠比较来排序"这一类里已经到顶了。但注意"靠比较"这个限制——基数排序不比较，它能突破这个下界。

8. 快速排序的最坏情况是什么？"熵最优"是什么意思？

专业回答

Proposition：Quicksort uses ~N²/2 compares in the worst case.

最坏情况：每次切分都极不均衡（输入已有序 + 每次取第一个元素当切分点）。

随机化的价值：<em>"the chance that they are invalid is less than the chance your computer will be struck by lightning."</em>

Proposition（三向切分）：Quicksort with 3-way partitioning is entropy-optimal.

"熵最优"：等于段已就位、不参与递归，运行时间与输入的信息量成正比。

📌 通俗解释

随机化没有消除最坏情况，只是让它变得极其不可能。对核反应堆、起搏器，这个区别是致命的——书里就是拿这几个例子来对照"最坏情况保证"的。

9. 为什么堆构造是线性时间？

专业回答

Proposition：Sink-based heap construction is linear time.

关键：从下往上 sink，而节点高度分布极不均匀：

层节点数sink 深度
倒数第二N/41
倒数第三N/82
根1lg N

Σ (N/2^(h+1))·h 收敛到 2N。而"从上往下 swim"是 N log N——同样的结构，两种方向，差一个 log。

📌 通俗解释

直觉会说"每个操作 O(log N)，建 N 个就是 N log N"。错在把"最坏的那个操作"乘了 N 次，而实际上最坏的操作只占极少数。

10. 二叉堆的两个定义里，哪两个设计要点值得注意？

专业回答

Definition：A binary heap is a set of nodes with keys arranged in a complete heap-ordered binary tree, represented in level order in an array (not using the first entry).

两个要点：① 完全不使用指针——用下标运算代替；② 不用第 0 项，让下标运算更简洁。

📌 通俗解释

数组下标是算术，指针是跳转。前者在真实机器上快得多——这是后面缓存那一层的伏笔。

11. 二叉搜索树的平均代价为什么不等于最坏代价？

专业回答

Proposition：Search hits in a BST built from N random keys require about ~2 ln N compares.

注意 2 ln N ≈ 1.39 lg N——比二分查找的 lg N 还差一点，但 BST 提供了二分查找没有的能力：动态插入。

"随机键"这个前提是关键：有序插入会让树退化成链表，高度变成 N。

📌 通俗解释

"平均 O(log N)"必须跟着"输入是随机的"这个前提。而真实数据里"有序"很常见（时间戳、自增 ID）——这是最经典的一类事故：测试用随机数据全过，上线遇到有序数据就挂。

12. 红黑树付出了什么代价？

专业回答

Proposition：The height of a red-black BST with N nodes is no more than 2 lg N.

"2"从哪来：它把 2-3 树的 3-节点拆成两个节点（一红一黑），最坏情况下所有链接都是红的。

代价：① 实现复杂度（旋转与颜色翻转）；② 常数因子（比 BST 的 1.39 lg N 还大）；③ 每节点多一个颜色位。

📌 通俗解释

红黑树买的是保险，不是速度。在随机数据上，未平衡的 BST 反而更快。

13. 哈希表的两条命题说了什么？"均匀散列"是假设还是结论？

专业回答

Assumption J：the hash function uniformly distributes keys.

Proposition（拉链）：the number of compares is ~N/M.

Proposition（线性探测）：with N = αM keys, probes is ~½(1 + 1/(1−α)) for search hits.

注意它叫 Assumption，不叫 Proposition。 所以——哈希表的 O(1) 从来不是被证明的，它是在一个假设下推导的。

线性探测的 α 效应：α → 1 时 1/(1−α) → ∞。代价不是线性上升，是急剧上升。

📌 通俗解释

对手可以故意构造让所有键碰撞的输入——这就是哈希碰撞攻击，真实发生过，导致过某些 web 框架的 DoS 漏洞。所以现代实现会在散列里加随机种子。

14. 哪个符号表实现不支持有序操作？为什么？

专业回答

哈希表。因为键被散列函数打散了——"顺序"这个概念在它里面不存在。

书里的命题明确说 floor / ceiling / rank / select 这些操作"take time proportional to the height in a BST"——它们压根没有哈希表的版本。

📌 通俗解释

这是API 层面的错误，不是性能问题。不是"把哈希表优化一下"能解决的。

15. 图算法为什么必须同时用 V 和 E 表示复杂度？

专业回答

Proposition：DFS uses preprocessing time and space proportional to V + E.

为什么必须写 V+E：稠密图 E ~ V²，稀疏图 E ~ V，同一算法差一个数量级。

最常见的坑：用邻接矩阵实现 DFS → 遍历变成 O(V²)，即使图是稀疏的。

📌 通俗解释

说"这个图算法是线性"时必须说清是对 V 线性还是对 E 线性。

16. MST 和最短路径的前提强弱对比说明什么？

专业回答

算法前提代价
Prim / Kruskal任意连通带权图（无额外前提）E log V
Dijkstra非负权E log V
拓扑序最短路DAGE + V
Bellman-Ford无负环（最弱）E·V

——前提越弱，代价越高。

📌 通俗解释

"负权"这个前提在"距离""成本"这类语义里看起来完全合理，所以把 Dijkstra 用在有负权的图上是极常见的实现错误——程序不报错，只是偶尔给出偏大的答案。

17. Trie 换来了什么？哈夫曼的"最优"是什么意思？

专业回答

Trie 换来的核心能力是前缀查询：找"所有以 abc 开头的键"只需沿 a→b→c 走三步。哈希表做不到——它把键打散了，"前缀"不存在了。

Property：No prefix-free code uses fewer bits than the optimal prefix-free code.

它和 03 域的信息论怎么接：

MacKayalgs4
问题一个信源最少要多少比特？给定频率，怎么构造最短前缀码？
答案熵 H（下界，可达）哈夫曼编码（前缀码里最优）

两者之间有一个必须知道的间隙：哈夫曼的期望码长落在 [H, H+1)——它达不到熵，最多逼近。 MacKay 讲的算术编码能突破这个 1 比特的损失。

📌 通俗解释

"哈夫曼是最优的"是在"前缀码"这一类里的最优，而前缀码整体达不到熵。这是跨域引用时最容易出的错：把"A 领域里的最优"当成"A 领域的极限"。

18. 为什么 B 树在磁盘上重要，而在内存里没那么重要？

专业回答

红黑树B 树
节点大小1 个键一整页
高度（N=10⁹）约 60约 3
每次节点访问代价内存访问（纳秒）磁盘 I/O（毫秒）

在磁盘上：60 vs 3 次 I/O = 几秒 vs 几毫秒，差距是决定性的。

在内存里：algs4 的命题告诉你红黑树是 2 lg N，B 树没有明显优势。

但有一个现代的转折：现代 CPU 的缓存层级让"缓存行"也变成了一种"页"——所以 B 树（及变体）在内存数据库里重新获得了优势。<em>这是"硬件改变，结论改变"的又一个例子。</em>

📌 通俗解释

正确的说法不是"B 树适合磁盘"，而是"B 树适合访问节点很贵的地方"——而"多贵"取决于硬件。这个表述比前者耐久。

19. 同一个矩阵遍历为什么差 5 倍？

专业回答

两个版本只差索引顺序：mat[i][j] vs mat[j][i]。

C 的二维数组是行优先存储的——mat[i][0]、mat[i][1] 在内存里连续。

版本 1版本 2
访问顺序沿内存连续前进在行之间反复跳跃
每块搬进来用几次全部用上只用 1 次就丢
去内存次数N²/每块元素数N²

而两个版本的工作量完全一样——在 algs4 的代价模型下一样快。

📌 通俗解释

差距来自访问模式，不是来自算法。 而你可以通过重排循环来提高速度，不改变任何计算结果。

20. 两本书合起来，你对"程序为什么快或慢"的认识完整了吗？

专业回答

来源回答什么由谁覆盖

仍然缺的：GPU 与分布式性能 · 编译器优化的深处 · JIT 与动态语言 · 特定领域的性能。
