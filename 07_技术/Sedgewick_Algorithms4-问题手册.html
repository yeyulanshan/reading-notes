1这本书用哪四层解剖每一个数据结构？为什么"代价"要单独成一层？L1

说出四层的名称，并解释第四层（策略）为什么不能从第三层（代价）直接推出来。

展开答案
层问的问题
API · 抽象它对使用者承诺什么？
实现 · 机制数据放在哪、操作怎么做？
性能 · 代价代价多高、在什么条件下成立？
策略 · 选择什么时候用它、什么时候不用？

为什么代价单独成层：因为在算法里代价不是附带信息，它就是选择依据本身。OSTEP 的"抽象→机制→策略"三段式到了这里必须加一层，否则你无法在"红黑树 vs 哈希表"之间做决定。

为什么策略不能从代价直接推出——这是本题的关键。两个结构的平均代价可能一样，但假设完全不同：

红黑树哈希表
查找~2 lg N（保证）~N/M（平均，依赖散列均匀）
有序操作✅ 支持（floor/ceiling/范围查询）❌ 不支持
最坏情况对数（有保证）线性（无保证）

——如果你的应用需要"找出所有 100 到 200 之间的键"，哈希表的平均代价再低也没用，因为它压根不提供这个操作。所以选择依据是"你要什么操作"，不是"哪个平均更快"。

⚠️ 失败模式把这一层当成"背表"就会错失重点。四层的顺序不能颠倒：先问 API（我需要什么能力），再问代价（哪个实现能做到），最后才是选。先看性能表再选结构的人，常常选到一个做不到他要的事的结构。
2什么是"代价模型"？为什么不说"3-sum 是 O(N³)"？L1

说出代价模型的定义，并解释为什么书里的表述比"O(N³)"更严格。

展开答案

代价模型（cost model）的定义：明确定义什么是"基本操作"。

书里的原话："We focus attention on properties of algorithms by articulating a cost model that defines the basic operations."

3-sum 的代价模型是：访问数组元素的次数（读或写都算）。

为什么比 O(N³) 严格：

"O(N³)"代价模型 + Proposition
说的是什么一个上界，且忽略了常数确切的操作次数（含常数）
在什么衡量下通常指"时间"，但没说是哪种时间明确：数组访问次数
能不能比较两个实现不能（都写成 O(N³) 时看不出差别）能（~N³/2 vs ~N²log N）
Proposition（原文）
The brute-force 3-sum algorithm uses ~ N³ / 2 array accesses to compute the number of triples that sum to 0 among N numbers.

换个代价模型，命题就要重写。如果代价模型改为"算术运算次数"，或者"CPU 周期数"，~N³/2 就不成立了。这就是这本书的性格：它不说含糊的话。

⚠️ 失败模式把代价模型的结论当成"这个算法就是这个速度"。代价模型是人为选定的——它衡量的是你关心的那个东西。选错了代价模型，得到的结论再精确也是答非所问：在真实机器上，"数组访问次数"相同的两个实现，可能因为缓存而差 10 倍。

4栈和队列的链表实现与可扩容数组实现，各自的承诺是什么？L1

说出两条 Proposition 的准确差别，并说明这个差别在实际中意味着什么。

展开答案
Proposition（链表）
In the linked-list implementation of Bag, Stack, and Queue, all operations take constant time in the worst case.
Proposition（可扩容数组）
In the resizing-array implementation of Bag, Stack, and Queue, starting from an empty data structure, any sequence of N operations takes time proportional to N in the worst case (amortized constant time per operation).

两条承诺的差别就是"摊还"这个词的全部意思：

链表可扩容数组
承诺每一次操作都快平均下来快（序列总体）
有无尖峰无有——扩容那一次会慢
额外开销每个节点多一个引用（8 字节）有闲置容量

实际意味着什么：如果你的场景不能容忍偶发的延迟尖峰（实时系统、音视频播放、交互式界面），摊还保证不够用——某一次 push 会花掉几百倍的时间。这时必须用链表，或者用可扩容数组但预分配足够容量。

🔬 可跑验证 · 把"摊还"画出来
分别用链表和可扩容数组实现栈，压入 10⁶ 个元素，记录每一次操作的耗时并画成图。
预期：链表是一条平线；数组大部分平、偶发尖峰。
这张图就是"摊还"这个词的可视化——它会让你以后看到"amortized"就知道要问"尖峰多大、多久一次"。
⚠️ 失败模式"摊还 O(1)"被当成"O(1)"来用。两者对序列成立，对单次操作不成立。而"单次"恰恰是用户感受到的东西。
5在哪几种情况下根本不该指望"更快"？L1

说出第 6 章给出的判断标准，并解释"归约"和"不可解性"为什么放在一起讲。

展开答案

第 6 章把两件事放在一起：

  • 6.5 归约（reductions）——怎么把一个新问题"化"成一个已知问题
  • 6.6 不可解性（intractability）——怎么证明一个问题不可能有高效解法（1533 行，全书最长的一节）

为什么放在一起：因为归约是证明不可解性的工具。你要说明"问题 X 很难"，办法是把 X 归约到一个已知很难的问题——如果 X 能被高效解决，那个已知难的问题也能，矛盾。

书里给出的那个 Theorem 很能说明这一节的性质：

Theorem（原文）
Given a purported theorem (such as one for the Riemann Hypothesis), can you prove it is true using at most n symbols in some formal system such as Zermelo-Fraenkel set theory?

——它把"证明一个数学定理"本身当成一个计算问题。这是这一节的气质：它讨论的不是"怎么写代码"，是"计算这件事本身的边界"。

什么时候不该指望更快：

  1. 问题是NP 完全的，且输入规模大——这时该做的是近似解、启发式、或者约束问题规模，而不是继续优化常数
  2. 问题是不可判定的——那就根本没有算法
  3. 你已经在理论下界附近了——比如基于比较的排序，N lg N 是下界，再怎么优化常数也突破不了
Proposition（基于比较的排序下界）
No compare-based sorting algorithm can guarantee to sort N items with fewer than lg(N!) ~ N lg N compares.
⚠️ 失败模式把"这个问题很难"当成"放弃"的理由。书里讲的是"别指望精确高效解"，不是"别做"。正确的反应是换目标：近似、随机、或者把问题限制在一个可解的规模上。这也是这一域最缺的一课——OSTEP 讲"怎么把它做对"，图像处理讲"怎么把它做好"，而这里讲"有些事压根别指望做快"。

6为什么"翻倍测试的比值"能直接读出增长级？L2

说出比值与增长级的对应关系，并解释这个方法的原理。

展开答案

原理：如果耗时 T(N) ~ a·N^b，那么把 N 翻倍：

T(2N) / T(N) ≈ a(2N)^b / (aN^b) = 2^b

——比值只跟指数 b 有关，跟常数 a 无关。所以你不需要先知道公式，就能从数据里把 b 读出来。

翻倍后的比值增长级例子
1常数数组索引
2线性一次遍历
2（略大于 2）N log N归并排序
4N²选择排序
8N³暴力 3-sum

书里给的三个工具：Stopwatch（测时间）· DoublingTest（翻倍输入、打印耗时）· DoublingRatio（额外打印比值）。

为什么"略大于 2"就能认出 N log N：因为 2N·log(2N) / (N·log N) = 2·(1 + log2/log N)——当 N 很大时趋近 2，但总是略大于 2。而纯线性的比值恰好是 2，不多不少。

🔬 可跑验证 · 自己造一遍
写两个函数：一个 O(N²)（比如双重循环数对），一个 O(N log N)（比如先排序再双指针）。用 N = 10³, 2×10³, 4×10³, 8×10³ 各跑一遍，打印比值。
你应该看到 ≈4 和 ≈2（略大于 2）。如果你看到的不是这个，先怀疑你的测试代码而不是这个理论。
⚠️ 失败模式这个方法在 N 太小时不可靠——常数项和 JIT 预热会淹没增长级。另一个坑：如果你测的时间里有与 N 无关的固定开销（如启动、I/O），比值会被压向 1，让你误以为算法是线性的。
7归并排序的两条 Proposition 说了什么？为什么它是最优的？L2

说出比较次数的上下界，以及"渐近最优"的依据。

展开答案
Proposition
Top-down mergesort uses between 1/2 N lg N and N lg N compares to sort an array of length N.
Proposition
Bottom-up mergesort uses between 1/2 N lg N and N lg N compares to sort an array of length N.
Proposition（下界）
No compare-based sorting algorithm can guarantee to sort N items with fewer than lg(N!) ~ N lg N compares.
Proposition（渐近最优）
Mergesort is an asymptotically optimal compare-based sorting algorithm.

"渐近最优"的依据：下界是 ~N lg N，而归并排序的上界是 ~N lg N——上界和下界撞上了，所以不可能更快（在基于比较的模型里）。

下界怎么来的（这是本题最有价值的部分）：用决策树。N 个元素有 N! 种排列，每次比较只有两个结果，所以一棵高为 h 的决策树最多有 2^h 个叶子。要区分 N! 种情况就需要 2^h ≥ N!，即 h ≥ lg(N!) ~ N lg N。

🔬 可跑验证 · 撞一撞下界
实现归并排序并统计实际比较次数，与 N lg N 对比。
你会看到实际次数落在 1/2·N lg N 到 N lg N 之间——这就是书里那个区间的来处。然后试着改改（比如对小数组用插入排序做阈值切换），看能不能把常数压下去。你会发现：能压常数，压不动增长级。
⚠️ 失败模式把"基于比较的下界"当成"所有排序的下界"。它只在"只能通过比较获取元素顺序信息"这个前提下成立。基数排序不比较，它"看"键的位，所以能突破 N lg N——这本书第 5.1 节讲的就是它。这就是为什么"下界"这个词永远要跟着"在什么模型下"。
8快速排序的最坏情况是什么？三向切分为什么被单独提出来？L2

说出两条 Proposition，并解释"熵最优"的含义。

展开答案
Proposition（最坏情况）
Quicksort uses ~N²/2 compares in the worst case.
Proposition（三向切分）
Quicksort with 3-way partitioning is entropy-optimal.

最坏情况是什么：每次切分都极不均衡——比如每次都切出一个空子数组。这发生在输入已经有序且每次都取第一个元素当切分点时。

于是加随机化：随机打乱或者随机选切分点。书里说随机化保证的价值："the chance that they are invalid is less than the chance your computer will be struck by lightning."——比被闪电击中还不可能失效。

"熵最优"是什么意思：如果输入里有大量重复键，三向切分把数组分成"小于 / 等于 / 大于"三段，等于段的元素已经就位，不参与递归。于是运行时间与输入的"信息量"成正比——这正是 Shannon 熵的形状。

这一条的跨域意义：这是 algs4 里唯一一个直接用"熵"命名的结论，而熵是 03_自然与数学 里 MacKay 那本的核心量。两本书在这里接上了：MacKay 给你熵的定义和下界，algs4 给你一个达到那个下界的算法。

⚠️ 失败模式以为"随机化 = 消除了最坏情况"。它没有消除最坏情况，它只是让最坏情况变得极其不可能。对核反应堆、心脏起搏器、汽车刹车这类场景，这个区别是致命的——书里就是拿这几个例子来对照"最坏情况保证"的用途的。另一类事故：如果你的比较函数本身有问题（比如不一致），三向切分会原地打转甚至越界。
9优先队列的四条 Proposition 说了什么？为什么堆构造是线性时间？L2

说出插入/删除的代价界、堆构造的代价、以及堆排序的代价。

展开答案

先看两个 Definition：

Definition
A binary tree is heap-ordered if the key in each node is larger than (or equal to) the keys in that node's two children (if any).
Definition
A binary heap is a set of nodes with keys arranged in a complete heap-ordered binary tree, represented in level order in an array (not using the first entry).

注意第二个定义的两个要点：① 完全不使用指针——用数组的下标运算代替指针（k 的子节点是 2k 和 2k+1）；② 不用第 0 项，这样下标运算更简洁。

然后是命题：

Proposition
The largest key in a heap-ordered binary tree is found at the root.
Proposition
In an n-item priority queue, the heap algorithms require no more than 1 + lg n compares for insert and no more than 2 lg n compares for remove-the-maximum.
Proposition
Sink-based heap construction is linear time.
Proposition
Heapsort uses fewer than 2 n lg n compares and exchanges to sort n items.

为什么堆构造是线性时间——这是本题最有价值的部分，因为直觉上会算成 N log N。

关键：从下往上 sink，而不是从上往下 swim。而且节点的高度分布极不均匀：

节点所在层节点数sink 的最大深度
倒数第二层N/41
倒数第三层N/82
根1lg N

——绝大多数节点的 sink 深度极小，只有极少数节点要沉得深。把 Σ (N/2^(h+1))·h 求和，结果收敛到 2N，是线性的。

而如果用"从上往下 swim"建堆，代价是 N log N——因为那时候每个新节点都要往上浮。同样的结构，两种构建方向，代价差一个 log。

🔬 可跑验证 · 两种建堆方向的差距
分别实现"逐个 swim"和"从下往上 sink"两种建堆，用翻倍测试测比值。
预期：swim 版的比值 ≈2（略大于 2，即 N log N），sink 版的比值 ≈2（纯线性）。
这两个都"≈2"但意义不同——这正是为什么要看 N 大时的稳定性，而不是只看一次测量。
⚠️ 失败模式用"每个操作 O(log N)"推出"建 N 个元素要 O(N log N)"。这个推理错在把"最坏的那个操作"乘了 N 次，而实际上最坏的操作只占极少数。这就是摊还分析的思想，和栈那一题是同一个道理。
10并查集从 quick-find 到加权 quick-union，代价是怎么降下来的？L2

说出四个版本的代价，以及那个关键的 Corollary。

展开答案
版本findunion问题
quick-find1Nunion 太贵
quick-union~N（最坏）取决于树高树可能退化
加权 quick-union~lg N~lg N—
路径压缩（+加权）接近常数（摊还）接近常数—
Proposition（quick-find）
The quick-find algorithm uses one array access for each find() and between N and 2N−1 array accesses for each union().
Corollary（加权 quick-union）
For weighted quick-union with n sites, the depth of any node is at most lg n.

关键在于"加权"那一步：不加权时，union 可能把大树挂到小树上，树越来越高。加权指的是总是把小的树挂到大的树上——这样一来，任何一个节点的深度每次增加，它所在的树至少翻倍，所以深度最多是 lg N。

这个论证很漂亮：它不追踪树的形状，只追踪"节点的深度增长一次意味着树翻倍"这件事。

🔬 可跑验证 · 让树退化给你看
实现不加权的 quick-union，然后按 (0,1), (1,2), (2,3), ..., (N-1,N) 的顺序 union。
你会得到一条链，find(N) 要 O(N) 步。然后换成加权版本跑同样的序列，深度变成 O(log N)。
这个实验最好玩的地方是：输入顺序完全一样，只是换了个挂树规则。这就是"机制决定代价"的直观证明。
⚠️ 失败模式以为"并查集就是快的"。四个版本的差距在 N=10⁶ 时是天壤之别（从几小时到几毫秒）。而且注意：加权用的是"树的大小"或"秩"，不是"高度"——用大小更容易维护，效果一样。
11二叉搜索树的平均代价为什么不等于最坏代价？L2

说出 BST 的两条 Proposition，并说明"随机键"这个前提的重要性。

展开答案
Proposition（命中）
Search hits in a BST built from N random keys require about ~2 ln N compares, on average.
Proposition（插入与未命中）
Insertion and search misses in a BST built from N random keys require about ~2 ln N compares, on average.
Proposition（有序操作）
Search, insertion, finding the minimum, finding the maximum, floor, ceiling, select, and rank all take time proportional to the height in a BST.

"随机键"这个前提是全题的要点。注意 2 ln N ≈ 1.39 lg N——比二分查找的 lg N 还差一点，但 BST 提供了二分查找没有的能力：动态插入（二分查找的有序数组插入要 ~2N）。

那最坏情况呢：如果键是有序插入的，树会退化成一个链表，高度变成 N。而"随机键"这个假设在真实数据里经常不成立——比如从日志里读时间戳，从数据库里读自增 ID。

这就是红黑树存在的原因——它把保证从"平均"变成"最坏"。

🔬 可跑验证 · 让 BST 退化
实现一个不做平衡的 BST，然后：
① 用随机打乱的 1..N 插入，测量高度；② 用升序插入，测量高度。
预期：① 高度 ≈ 2 ln N ≈ 1.39 lg N；② 高度 = N。
N=10⁴ 时这两者分别是约 18 和 10000——这就是为什么"平均 O(log N)"这个说法必须跟着"输入是随机的"这个前提。
⚠️ 失败模式把"平均 O(log N)"写进设计文档而不写前提。这是一类经典事故：测试用随机数据全过，上线遇到有序数据就挂。
12红黑树的"2 lg N 高度"是怎么保证的？它换来了什么？L2

说出红黑树的关键 Proposition，并说明它相对于 BST 付出了什么代价。

展开答案

先看 2-3 树（红黑树的思想来源）：

Definition
A 2-3 search tree is a tree that either is empty or: (2-nodes have one key and two links; 3-nodes have two keys and three links; perfectly balanced).
Proposition（2-3 树）
Search and insert operations in a 2-3 tree with N keys are guaranteed to take time proportional to lg N.

然后是红黑树——它用"红色链接"把 3-节点编码成两个 2-节点，从而用一个普通的 BST 结构实现 2-3 树：

Proposition（红黑树高度）
The height of a red-black BST with N nodes is no more than 2 lg N.
Proposition（红黑树操作）
In a red-black BST, search, insert, delete, min, max, floor, ceiling, rank, select, and range queries take logarithmic time in the worst case.

"2 lg N"里的 2 从哪来：红黑树把 2-3 树的每个 3-节点拆成两个节点（一红一黑）。最坏情况下所有链接都是红的，于是高度翻倍。所以是 2 lg N 而不是 lg N。

付出的代价：

代价说明
实现复杂度插入/删除要做旋转与颜色翻转，边界情况多。这是它最大的代价
常数因子2 lg N 比 BST 的 1.39 lg N 还大一点
空间每个节点多一个颜色位

换来了什么：最坏情况保证。这一条是决定性的——只要你的数据可能有序，BST 就不可靠。

⚠️ 失败模式以为红黑树"总是比 BST 快"。在随机数据上，未平衡的 BST 反而更快（常数更小）。红黑树买的是保险，不是速度。——这也是为什么很多标准库在实现 map 时会选更简单的结构，或者干脆用 B 树（见第 6.2 节）。
13哈希表的两条 Proposition 说的是什么？"均匀散列"是假设还是结论？L2

说出拉链法与线性探测法的代价，并指出书里对散列假设的用词。

展开答案
Assumption J（均匀散列假设）
The hash function that we use uniformly distributes keys among the integer values between 0 and M−1.

注意它叫 Assumption（假设），不叫 Proposition（命题）。——这是本题最重要的一处细节。Sedgewick 明确区分了两类陈述：

类型含义举例
Proposition可证明的结论红黑树高度 ≤ 2 lg N
Property在实际使用中观察/经验成立的"Quicksort is the fastest general-purpose sort"
Assumption假定成立、无法证明的前置条件均匀散列

所以哈希表的性能结论是这个形状的：

Proposition（拉链法）
In a separate-chaining hash table with M lists and N keys, the number of compares is ~N/M (for search miss and insert).
Proposition（线性探测）
In a linear-probing hash table of size M with N = αM keys, the number of probes is ~½(1 + 1/(1−α)) for search hits.

——而这两个 Proposition 的成立都依赖 Assumption J。换句话说：哈希表的 O(1) 从来不是被证明的，它是在一个假设下推导的。

线性探测那个公式的后果很值得注意：当 α → 1（表快满）时，1/(1−α) → ∞。所以线性探测必须留出空间——实践中 α 通常控制在 1/2 到 1/8 之间。

🔬 可跑验证 · 体验 α 的威力
实现线性探测哈希表，用同一个数据集测 α = 0.25 / 0.5 / 0.75 / 0.9 时的平均探测次数。
预期：探测次数不是线性增长，而是在 α 接近 1 时急剧上升。
然后试一个"坏的"散列函数（比如把 ASCII 值直接相加），你会看到即使 α 很小，性能也崩了——因为 Assumption J 被违反了。
⚠️ 失败模式把哈希表当成"有保证的 O(1)"。这是最普遍的一类误解。现实中的事故几乎都出在 Assumption J：对手可以构造让所有键碰撞的输入（这就是哈希碰撞攻击，某些 web 框架因此被 DoS）。所以现代实现会在散列里加随机种子——把"对手可控"变成"对手不可控"。
14图算法：DFS 为什么能在"预处理时间与空间"上做到线性？L2

说出 DFS 的命题，并解释"预处理"这个说法的含义。

展开答案
Proposition
DFS marks all the vertices connected to a given source in time proportional to the sum of their degrees.
Proposition
DFS uses preprocessing time and space proportional to V + E.

"预处理"的含义：先花 O(V+E) 的时间把图走一遍、建好辅助数组（marked[]、edgeTo[] 等），之后每次查询只需常数时间。

为什么是 V+E 而不是 V²：因为你只访问每条边常数次。这也解释了为什么图算法的复杂度必须同时用 V 和 E 表示——稠密图 E ~ V²，稀疏图 E ~ V，同一算法的实际代价差一个数量级。

书里给的另一条哲学性的 Proposition：

Proposition
For any vertex v reachable from s, the path in the tree gives a shortest path from s to v in the graph. （对无向图的 BFS 而言）

这个"预处理"的思路就是图算法的通用模式：先付一次线性成本建立结构，之后所有查询都便宜。这也是"数据结构"这个概念在图上的体现。

🔬 可跑验证 · V+E 与 V² 的区别
生成两种图：稀疏（E ≈ 2V）和稠密（E ≈ V²/2），都在 DFS 上跑翻倍测试。
预期：稀疏图的比值 ≈2（线性）；稠密图的比值 ≈4（平方）。
同一个算法的代码，复杂度随图的稠密度变化——这就是为什么图算法的复杂度必须写成 O(V+E)。
⚠️ 失败模式用邻接矩阵实现 DFS 而不自觉。邻接矩阵的遍历是 O(V²)，即使图是稀疏的。数据结构的选择（邻接表 vs 矩阵）直接决定了算法复杂度——这是"机制决定代价"在图上的版本。
15最小生成树和最短路径的四条经典命题，前提分别是什么？L2

说出 Prim、Kruskal、Dijkstra、Bellman-Ford 各自的命题与适用前提。

展开答案

先看支撑 MST 两条算法的那条贪心命题：

Proposition（Greedy MST algorithm）
The greedy algorithm computes the MST of any connected edge-weighted graph. （在切分定理下：给定任意切分，横切边中权重最小的边一定属于某棵 MST）
Proposition（Prim）
Prim's algorithm computes the MST of any connected edge-weighted graph.
Proposition（Kruskal）
Kruskal's algorithm computes the MST of any connected edge-weighted graph.

MST 的两条命题都强调"任意连通带权图"——没有额外前提。这是它们比最短路更强的地方。

最短路径就不一样了，前提很重要：

Proposition（Dijkstra）
Dijkstra's algorithm solves the single-source shortest-paths problem in edge-weighted digraphs with nonnegative weights.
Proposition（拓扑序）
By relaxing vertices in topological order, we can solve the single-source shortest-paths problem in time proportional to E + V for edge-weighted DAGs.
Proposition（Bellman-Ford）
The Bellman-Ford algorithm solves the single-source shortest-paths problem in edge-weighted digraphs with no negative cycles.
算法前提代价为什么
Dijkstra非负权E log V贪心：一旦确定就永不回头——负权会破坏这个
拓扑序DAG（无环）E + V拓扑序天然保证"之后再无更新"
Bellman-Ford无负环E·V放弃贪心，反复松弛 V 轮

这张表本身就是全题的价值：前提越弱，代价越高。Dijkstra 要求非负权（最强前提）→ 最快；Bellman-Ford 只要能没有负环（最弱前提）→ 最慢。

🔬 可跑验证 · 用负权把 Dijkstra 打坏
构造一个有负权边的小图，跑 Dijkstra，看它给出错误答案。
典型反例：s → a 权 1、s → b 权 2、b → a 权 −2。Dijkstra 会先确定 a（距离 1），但真正的最短路是 s→b→a = 0。
跑这个例子的价值在于：它把"前提"从一个抽象的说明变成了你看得见的错误答案。
⚠️ 失败模式把 Dijkstra 用在有负权的图上。这是非常常见的实现错误，因为负权在"距离""成本"这类语义里看起来完全合理。而它的症状很隐蔽：程序不报错，只是偶尔给出偏大的答案。

16你要维护一个"随时插入、随时查第 k 小"的集合。选什么结构？L3

给出答案、理由，以及这个选择付出的代价。

展开答案

答案：平衡 BST（红黑树），因为它提供 select(k) 和 rank(key)。

书里那条命题就是为这个问题写的：

Proposition
Search, insertion, finding the minimum, finding the maximum, floor, ceiling, select, and rank all take time proportional to the height in a BST.

关键是书里的一句话："To implement select and rank efficiently, we store in each node the number of nodes in its subtree."——用一个额外的计数字段，把"第 k 小"变成一次下行走。而红黑树保证高度是 2 lg N，所以是保证的对数时间。

为什么不能选哈希表：哈希表不维护顺序，"第 k 小"这个概念它压根不提供。这就是第 1 题讲的：先问 API，再问代价。

为什么不能选堆：堆能给你"最小"，但不能给你"第 k 小"——堆只保证根是最值，内部没有全局顺序。

付出的代价：① 红黑树的实现复杂度；② 每个节点多一个计数字段（空间）；③ 常数因子比哈希表大。

⚠️ 失败模式如果 k 是固定的或者变化很小（比如只查中位数），维护两个堆比红黑树更划算——一个最大堆存小半、一个最小堆存大半。数据结构的选择取决于"查询模式"，不只是"支持什么操作"。
17一个程序要读 10⁸ 个键做去重。用哈希表还是红黑树？L3

给出判断，并说明在什么条件下这个判断会反转。

展开答案

如果只需要去重（不需要顺序）→ 哈希表。

理由：去重只需要"键在不在"，这是哈希表最擅长的。红黑树做同样的事要花 ~2 lg N 次比较，而哈希表在 α 合理时接近常数。N = 10⁸ 时，lg N ≈ 27，差距是几十倍。

什么条件下反转：

条件改选原因
需要有序输出（比如按序打印）红黑树哈希表拿不到顺序，你还要额外排一次（N log N）
需要范围查询（所有在 [a,b] 内的键）红黑树哈希表不支持
输入可能被对手构造红黑树Assumption J 被破坏 → 哈希表退化成链表
内存受限看情况哈希表要留空位（α），红黑树每个节点要两个指针 + 颜色位
键本身有序（如时间戳）且用未平衡 BST哈希表BST 会退化成 O(N) 每个操作

还有一个现实中的第三选择：如果只要"近似去重"（允许误判），布隆过滤器用远少于哈希表的内存就能做到——代价是有假阳性、不能删除。这是"精度换空间"的典型取舍。

⚠️ 失败模式只按"平均复杂度"选。工程判断里真正决定的是"最坏情况能否接受"和"需不需要顺序"。
18图像处理的滤波为什么用数组而不是链表？L3

从访问模式回答，并说明这引出 algs4 的哪个局限。

展开答案

因为滤波的访问模式是"相邻访问"。一个 3×3 卷积核对每个像素要读它周围的 8 个邻居——地址连续。

结构相邻访问的代价
数组相邻元素在内存里相邻——一次缓存行载入能拿到几十个元素
链表每个节点分散在堆上，每次访问都可能是一次缓存缺失

这就是 algs4 不管的那一层（我们讨论过的第③层）。在 algs4 的代价模型里，数组和链表的"访问一次"是同等代价（都是 1 次"数组访问"或 1 次"链接跳转"）。在真实机器上，这两者可能差 100 倍。

所以正确的说法是：

  • 在 algs4 的代价模型下：数组和链表都是 O(N) 遍历
  • 在真实硬件上：数组遍历比链表快得多，因为空间局部性

这正好说明为什么这两本书要配对读：algs4 告诉你"理论上一样快"，Dive into Systems 告诉你"实际上为什么不一样"。

🔬 可跑验证 · 量出这个差距
用同一种语言，实现一个数组和一个链表，各存 10⁷ 个整数，然后各遍历一遍求和，计时。
预期：数组明显更快（在这类场景下常见 3–10 倍，元素更大时差距更大）。
然后做一个"随机访问"版本（打乱访问顺序）——数组的优势会缩小甚至消失。这一步会告诉你：优势来自访问模式，不是来自数组本身。
⚠️ 失败模式看到"数组更快"就得出"数组总是更好"。一旦访问模式变成频繁的中间插入/删除，链表的优势就出来了（数组每次插入要搬移 O(N) 个元素）。真实工程里常用的折中是"分块链表"（deque / unrolled list）——把两者的优点各拿一半。
19压缩：为什么"没有前缀码用更少比特"？这和 03 域怎么接？L3

说出那条 Property，并把它与信息论的源编码定理对照。

展开答案
Property
No prefix-free code uses fewer bits than the optimal prefix-free code. （即哈夫曼编码是最优的前缀码）

这条 Property 在说什么：在所有"任何码字都不是另一个码字前缀"的编码里，哈夫曼编码的期望码长是最小的。它是一个最优性结论——所以书里标为 Property（在实际使用中成立、可论证）。

它和 03_自然与数学 的 MacKay 怎么接——这是这一域与 03 域最硬的一条连接：

MacKay（信息论）algs4（算法）
问题一个信源最少要用多少比特表示？给定符号频率，怎么构造最短的前缀码？
答案熵 H（下界，且是可达的下界）哈夫曼编码（在前缀码这一类里最优）
关系给出理论上界给出一类实用编码里的最优解

两者之间有一个必须知道的间隙：哈夫曼编码的期望码长落在 [H, H+1) 之间——它达不到熵，最多逼近。（因为每个符号至少要 1 比特，而概率很小的符号其自信息远小于 1 比特。）

MacKay 那边讲的"算术编码"能突破这个 1 比特的损失，代价是计算复杂度。这就是"最优"这个词永远要跟着"在哪一类里"的又一个例子。

⚠️ 失败模式把"哈夫曼是最优的"读成"哈夫曼达到了理论极限"。它是在"前缀码"这一类里的最优，而前缀码整体达不到熵。这是跨域引用时最容易出的错：把"A 领域里的最优"当成"A 领域的极限"。
20为什么 B 树出现在"语境"这一章而不是"查找"那一章？L3

解释 B 树的设计目标与红黑树的根本差别。

展开答案

因为 B 树要解决的不是"比较次数"，是"磁盘访问次数"。

书里对 B 树的介绍很简洁，但它的设计目标是明确的：让树的高度极小，使每次查找只需很少几次磁盘 I/O。

红黑树B 树
优化的目标比较次数I/O 次数（页读取）
节点大小1 个键一整页（几百到几千个键）
高度2 lg Nlog_页大小 N（远小）
N = 10⁹ 时高度约 60约 3

为什么这很重要：如果每次比较都是一次内存访问，60 次和 3 次的差别是几十倍；但如果每次节点访问都是一次磁盘 I/O（毫秒级），那么 60 次和 3 次的差别是几秒 vs 几毫秒。

所以 B 树放在"语境"章是对的：它不是一个"更快的查找结构"，它是针对另一种硬件层级重新设计的结构。把它放进"查找"章会和红黑树比"谁的比较次数少"，那就完全问错了问题。

它和 OSTEP 的接口：文件系统的索引就是 B 树（或它的变体）。OSTEP 讲"为什么需要它"，algs4 讲"它怎么工作"。

🔬 可跑验证 · 换代价模型，换结论
实现一个简化 B 树（页大小 = 64 个键）和一个红黑树，都存 10⁶ 个键。用两种代价模型各统计一次：
① 统计 比较次数；② 统计节点访问次数。
预期：比较次数的差距不大（两者都是对数级）；但节点访问次数的差距是数量级的。
这个实验把第 2 题讲的"代价模型"从抽象变成了可测——同一个算法，换一个代价模型，优劣就反过来了。
⚠️ 失败模式在纯内存场景下用 B 树，然后觉得它"没那么快"。B 树的价值只在"访问节点很贵"的环境里体现。反过来，现代 CPU 的缓存层级让 B 树在内存里也重新有了优势（缓存行也是一种"页"）——这是"硬件改变，结论改变"的又一个例子。
21字符串问题为什么需要专门的数据结构？Trie 换来了什么？L3

说明 Trie 与哈希表在字符串场景下的差别。

展开答案

因为字符串有一个哈希表不利用的性质：共享前缀。

哈希表Trie
查找代价O(键长)（要算散列）O(键长)（逐字符下行）
前缀查询❌ 做不到✅ 天然支持
有序遍历❌✅（按字符序）
空间取决于 α取决于共享前缀的程度

Trie 换来的核心能力是前缀查询：找"所有以 abc 开头的键"只需要沿着 a→b→c 走三步，然后遍历那个子树。哈希表做不到这件事——因为它把键打散了，"前缀"这个概念不存在了。

这解释了为什么自动补全、拼写检查、IP 路由表都用 Trie（或它的压缩版本）。

  4. 5.4 正则——把模式变成自动机
  5. 5.5 压缩——用频率构造最优前缀码

这五节共享一个思想：不要跟字符"比较"，要利用字符的结构。

⚠️ 失败模式在键很长、前缀共享很少的场景用 Trie。Trie 的空间代价可能远大于哈希表——如果每个键的前几个字符都不同，Trie 会退化成一棵宽而浅的树，大量节点只有一个孩子。所以实践中常用压缩 Trie（Patricia/radix tree）来消除单孩子链。
22"排序应用"那一节给了什么策略性结论？L3

说出那条 Property，并解释为什么它是 Property 而不是 Proposition。

展开答案
Property
Quicksort is the fastest general-purpose sort.

为什么它是 Property 而不是 Proposition——这个区分很重要：

类型性质能否证明
Proposition数学结论能（如"归并排序比较次数在 ½N lg N 与 N lg N 之间"）
Property关于实际实现的观察不能——它依赖常数因子、内存访问模式、具体机器

"最快"这个判断无法证明，因为它取决于：常数因子、缓存行为、输入分布、比较操作本身有多贵。归并排序的比较次数下界比快排好，但快排在实践中通常更快——因为它的访问模式更局部化。

注意这条 Property 又一次指向了 algs4 的边界：它的结论"快排最快"不能由它自己的代价模型解释（按比较次数算，归并不是更差吗？），只能由真实硬件（缓存局部性）解释。这是"为什么必须配 Dive into Systems 读"的第三个理由。

第 2.5 节的策略性结论还有这些：

  • 大多数情况下用快排，但要注意重复键（用三向切分）
  • 需要稳定性时用归并（快排不稳定）
  • 小数组用插入排序（常数小，实践中快排实现常用 10 左右的阈值切换）
  • 堆排序是唯一既保证 N log N 又原地的——但常数大，实际慢
🔬 可跑验证 · 自己撞一次"最快"
实现快排、归并、堆排序，在同一台机器、同一组数据上测时间。
预期：快排通常最快，但它不稳定、最坏情况 N²。然后：
① 在大量重复键的数据上测——普通快排可能退化成 N²，三向切分版本不会；
② 在基本有序的数据上测——实现不好的快排会退化。
这个实验让你亲眼看到"最快"是一个带星号的结论。
⚠️ 失败模式把"快排最快"当成无条件结论直接写进技术选型。它在最坏情况下是 N²，而且不稳定。如果你的数据可能被对手构造（比如 web 请求参数排序），未随机化的快排是可以被攻击的——这是真实发生过的 DoS 漏洞类别。
23事件驱动模拟（6.1）为什么需要一个专用结构？L3

说明这个问题为什么不能直接用"排序 + 遍历"解决。

展开答案

因为事件的产生是动态的、依赖前面的结果。

书里给的三个例子——硬球模型、布朗运动、粒子碰撞——都有同一个结构：

  1. 从"最早的事件"开始处理
  2. 处理它会预测出新的未来事件（比如两个球碰撞后会各自撞上别的球）
  3. 新事件要插入到事件队列里
  4. 重复

为什么"排序 + 遍历"不行：事件不是预先知道的，它们是在模拟过程中被算出来的。所以你需要一个支持"取最小 + 随时插入"的结构——这正是优先队列。

方案取最小插入用在这里
预先排序的数组O(1)O(N)❌ 插入太贵
无序数组O(N)O(1)❌ 取最小太贵
二叉堆O(log N)O(log N)✅ 两边都便宜

这就是"数据结构"的意义：它让两种操作同时便宜。

⚠️ 失败模式忽略"事件的失效"。当两个粒子碰撞后，它们原本"将在未来相撞"的那些预测就作废了——如果只是简单地把新事件压入堆而不作废旧的，你会处理到一堆不可能发生的事件。书里对这类的处理通常用"惰性删除"（取出来时检查是否仍然有效）。这是事件驱动模拟里最容易出 bug 的地方，而且症状是"模拟结果偶尔不对"，极难调试。

24Proposition、Property、Assumption 三者的区别为什么重要？L4

各举一例，并说明混淆它们会导致什么后果。

展开答案
类型含义例子能不能依赖
Proposition可证明的数学结论红黑树高度 ≤ 2 lg N；堆排序 < 2n lg n✅ 总是（只要前提满足）
Property实际使用中的观察Quicksort is the fastest general-purpose sort⚠️ 看环境
Assumption无法证明的前置假定均匀散列假设❌ 可能不成立

混淆它们的后果，逐条说：

  1. 把 Assumption 当成 Proposition——最严重。你会以为哈希表有 O(1) 的保证。而实际上它依赖一个可以被破坏的假定，这就是哈希碰撞攻击的原理。
  2. 把 Property 当成 Proposition——你会以为"快排总是最快"。而它依赖常数因子与硬件，换个机器或者换个数据分布就可能不成立。
  3. 把 Proposition 的前提忘掉——比如"BST 查找 ~2 ln N"忘掉"随机键"这个前提，就会在有序数据上遇到 O(N) 的事故。

为什么这个区分是本书最有价值的设计之一：绝大多数教材把所有结论写成同一种格式（"定理"或"结论"），而这本书用三种标记明确告诉你每个结论的可信度类型。这是一种"证据等级标注"——和我们在 08 域为米勒做的 A/B/C 分级是同一个思路。

⚠️ 失败模式（这条本身也有边界）即使标成 Proposition，它的成立仍然依赖代价模型。"堆排序少于 2n lg n 次比较与交换"在"比较与交换"这个代价模型下成立；换成"缓存缺失次数"，结论可能完全不同。所以严格说：Proposition = 在给定代价模型下可证明的结论。

26为什么"渐近最优"这个说法必须跟着"在哪一类算法里"？L4

用归并排序和基数排序的对照回答。

展开答案

归并排序是"基于比较的排序里渐近最优"。

Proposition
Mergesort is an asymptotically optimal compare-based sorting algorithm.

注意 "compare-based" 这个限定词——它不能去掉。

基数排序（5.1 节）不比较，它把键看成字符序列，逐位分桶。所以它不受 lg(N!) ~ N lg N 下界的约束，可以在特定条件下做到线性。

归并排序基数排序
代价模型比较次数字符访问次数
代价~N lg N~W·N（W = 键长）
下界撞到下界（在比较模型里）不受那个下界约束
谁更快取决于 lg N 与 W 谁大——没有绝对答案

所以"最优"永远要问两个问题：

  1. 在哪个代价模型下？（比较次数 vs 字符访问次数 vs 缓存缺失）
  2. 在哪一类算法里？（基于比较的 vs 利用键结构的）

这两个问题问完了，"最优"才是一个有内容的说法。这和 03 域 MacKay 讲的"定理的前提"是同一件事——跨域的同一条纪律：结论必须和前提一起引用。

⚠️ 失败模式看到"最优"就停止思考。算法领域几乎每一个"最优"都带一个隐含的模型假设。附带一提：基数排序需要额外的桶空间，而且不稳定（除非用特定变体）——所以"能突破下界"不等于"应该用它"。
27"摊还分析"和"平均情况分析"的区别是什么？L4

这两者经常被混淆，但它们对输入的要求完全不同。

展开答案
平均情况分析摊还分析
对什么求平均输入的概率分布操作序列
需要什么假设需要假定输入的分布（如"键是随机的"）不需要输入分布假设
保证强度弱——分布不成立就失效强——对任意操作序列都成立
例子BST 查找 ~2 ln N（要求随机键）可扩容数组：任意 N 次操作总共 O(N)

这个区别的实践含义很大：

  • "BST 平均 O(log N)"——如果输入有序就完全失效
  • "可扩容数组摊还 O(1)"——不管你怎么用它，N 次操作总共就是 O(N)

所以摊还是更强的一种保证：它不依赖你对输入的猜测，只依赖"操作序列"这个前提本身。

但摊还也有它自己的软肋：它是对序列的保证，不是对单次操作的保证。所以对"每次操作都有硬实时要求"的场景，摊还不够用。

书里把这两者放在同一个"coping with dependence on inputs"的标题下，正是因为它们都是对付"输入依赖"的手段——但可靠程度不同。

⚠️ 失败模式在设计文档里写"平均 O(log N)"而不写分布假设。读文档的人会把它当保证用。更稳妥的写法是把两者分开写：最坏情况是什么（有保证）、平均情况是什么（在什么假设下）、摊还情况是什么（对序列）。
28读完这本书，你应该能回答哪三类问题？L4

展开答案
