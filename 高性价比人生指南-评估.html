三 · 它做对的三件「底层认知」的事

① 它把「证据强度」做成了一个字段，不是一句形容词

这是我该学的地方。我自己的项目只区分「已核对原文 / 未核对」， 而它分了 A / B / C 三级，并且在 readme 里给了每一级的判据。

而且它在 readme 里给了三级各自的判据（照原样）：

等级它给的定义
A有具体数字可查，出处是多项研究合并起来的荟萃分析、跟踪很多人很多年的大型队列，或者随机分组的试验（RCT），能说出降了多少（HR、RR、下降百分比）
B有研究支持，但说不出一个确切数字；或者只有小样本、单独一项研究撑着
C作者自己的经验，或者大家公认的做法，没有直接的研究文献

这个分级的实质是「能不能说出一个确切的数字」，而不是笼统的「靠不靠谱」—— A 级的判据是「能说出降了多少」，B 级是「说不出确切数字」，C 级是「没有研究文献」。 这是一个可以照着判的规则，不是模糊的形容词。

更细的是它的术语表——它把研究方法本身解释了，而且解释里带着这条方法的弱点：

· 队列：队列研究。挑一大群人跟踪很多年，记录谁出了事。 能看出两件事常一起出现，但不足以证明是前一件事造成了后一件事。 · 观察性：观察性研究。研究者只在旁边记录，不安排谁做、谁不做。 结果容易被别的因素带偏（见本表的混杂、反向因果两条），数字要打点折看。 · 混杂：有第三个因素同时牵动着前因和后果，让两件事看起来像有因果。 比如爱吃菜的人往往也更爱运动，分不清是哪一样在起作用。 · 反向因果：……

这不是科普话术——它是在教读者怎么打折看它自己给的数字。

还有一条我漏看了的：在证据分级那一节，它写「全书 669 条中 A 级 437 条、 B 级 177 条、C 级 55 条，另有 69 条标注了争议、3 处标注了……」—— 也就是说，除了 A/B/C，还有一层「争议」标记。

② 它把四种「货币」明确分开，并且拒绝互相折算

死亡率的数字、时间精力的数字、金钱的数字和法律后果，各算各的，不互相折算。 这四样对应检索页上那四个「换回什么」，彼此之间不比大小。

这一条相当硬。 通常的「人生建议」会把「多活三年」和「省五万块」放进一个性价比公式里算总分—— 而那样做必须假定一个「一条命值多少时间」的汇率，而那个汇率是任意设的。

它拒绝设那个汇率。 每条的 口径= 字段（如上例的 口径=死亡率） 就是在标明「这一条的收益是用哪种货币计的」。

③ 它反复标出自己的边界，而且标得很不客气

  • 「成本那一栏是作者按市面价格的粗略估计，只用来互相比较，不要拿去引用」
  • 「不用全做：这是按性价比排好的备选单，不是任务清单——挑走一两条就算数， 作者自己也没做到其中大部分」
  • 对陌生人出不出手：「不替你把它算成非做不可的理由」
  • 还专门声明「从未发行、也不会发行任何代币」，并把「别买虚拟货币」单列为第 5 节第 45 条

「作者自己也没做到其中大部分」这句话，是这份材料里最诚实的一句。

四 · 它与「底层」是什么关系

结论：不能平级并入，但有两处高价值的用法。

原因在目标不同：

「底层」知识库《高性价比人生指南》
回答的问题为什么（解释世界怎么运作）做什么（我该怎么办）
单位一本书 → 一份解释框架一个决定 → 一条可执行建议
证据的作用检验一个解释决定要不要做
失败的形态解释被反驳建议无效或有害
它的书26 本书，全是解释类43 份文档，绝大部分是行动类

所以把它放进 00_中文原典（原典库）或任何一个域，都会破例—— 那些域的定义都是「一句话的问题」（如 01「认识本身怎么才可能」）， 而这本书不是对一个问题的回答，是几百个不同问题的清单。

但有两种用法是真正有价值的

用法一 · 把它当引用强度的外部参照

这是最有价值的一处。 我的项目里引文只有两种状态（核对过 / 没核对）， 而它给的 A/B/C 分级可以直接借来当一个更细的口径。

更关键的是：它让我看到我自己的引文核对缺了什么。

  • 我做的：这句话是不是原文（字面准确性）
  • 它做的：这句话背后的证据有多硬（证据强度）

这是两件不同的事，而我只做了前一件。 例如《亲密关系》里那些结论，我核对了它们是原文， 但从没标注过那些结论本身是 A 级（多项 RCT / 荟萃）还是 C 级（单个观察研究）—— 而 Miller 在每个结论后面其实都带了样本与设计。

用法二 · 用它当「可检验断言」的来源，去和在库的解释类书对撞

它的 669 条里大量是可检验的断言，而其中一部分与我库里那 26 本书的立场直接相关：

它的条目类型可能撞上的在库书
「某某筛查能降低死亡率」（证据等级 A）《思考，快与慢》的基率忽视与可得性偏差
「这一类风险被高估/低估」卡尼曼的风险认知
「不要相信直觉的某某判断」《无穷的开始》的「好解释 vs 直觉」
应急、急救、法律红线的决策规则《非对称风险》的「切身利害」与「遍历性」
「恋爱和结婚划不划算」的核算《亲密关系》的相互依赖理论 · Fromm 的「交换 vs 给予」
「学什么技能划算」《科技想要什么》的技术方向论

这一条能直接变成一份跨域产出：《高性价比人生指南》× 项目在库书目 · 对照—— 它的价值在于：这 669 条里有证据等级的，正好可以用来检验那 26 本书的哪些主张在实务上站得住。

五 · 它没有的东西（我库里有的）

为了不把它捧过头，也要说清它缺什么：

缺为什么重要
不解释机制它说「系安全带降 45%」，不说「为什么人的直觉低估低概率高后果的风险」。给出的是行动，不是理解。
不做跨书连接它自成一个封闭的建议体系，不引用别的框架（除了它自己的 docs）。项目最看重的那件事（书与书之间的海）它不做。
没有「我的判断」与「原文」的区分它的条目是混合体：官方统计 + 自己的推算 + 判断。它标了证据等级，但没有逐句标出哪一句是原文、哪一句是它自己的推论
时效性风险法律、医保、社保部分「按中国大陆现行规定写」——这一部分会过时，而它无法自我更新
覆盖面的偏向34 篇里健康与安全占了大半。认识论、社会结构、历史因果这些「底层」问题它不碰。

六 · 我建议的处理方式

建议：收进来，但作为「原料库」的独立一类，不做平级的书

具体三条：

  1. 不放进 00_中文原典——那是个古典原典库，放一个 21 世纪的应用清单会破坏它的性质。
  1. 建一个 11_实用决策库（或类似名），只放这一类材料， 并在 README 里写清它与 01–10 域的区别： 10 个域回答「为什么」，这一个回答「做什么」，两者不互相替代。 这一条正好呼应项目已有的原则——域的划分要按「问题」，不能按「来源」， 而「我该怎么办」是一个独立的问题，不是任何现有域的子问题。
  1. 先把那三个文件的问题解决：
  • 离线 HTML 是单页应用，数据靠 JS 渲染 —— 如果直接放进站点，内容显示不出来（只有壳）。
  • 要么把 43 篇文档抽出来重新渲染（工作量大，但可控）， 要么只作本地留档，不进站点，PDF 与 epub 用作阅读。
  • 我倾向先抽 readme + 34 篇的分篇清单（parts 的键就是完整目录）， 做成一份「它有什么」的索引，而不是整本上线。

七 · 一句话结论

它的证据纪律比我自己的项目更细，值得学它的 A/B/C 分级与「四种货币不互相折算」这两条； 但它回答的是「做什么」，而「底层」回答的是「为什么」—— 两者的价值不重叠，所以不能平级并入，只能作为「可检验断言的来源」引入。

最有价值的一处用法不是读它，而是用它那 669 条里带证据等级的断言， 去检验我库里那 26 本书的哪些主张在实务上站得住。
