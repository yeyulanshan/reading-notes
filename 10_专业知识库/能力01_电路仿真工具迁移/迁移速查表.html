迁移速查表：Multisim / PSpice → LTspice

符号、器件、指令的对照表

从 Multisim 迁到 LTspice 时手边要放的那一页。

迁移速查表：Multisim / PSpice → LTspice

用法：左边找你熟悉的操作，右边是 LTspice 的做法。 标记说明：★ = 迁移时最容易踩的坑。

一、最根本的一条：从「画图」转向「读网表」

MultisimLTspice
你的主要工作在画布上放元件、连线能读能改网表，也能画图
网表在哪藏在背后（Transfer > Netlist）就是那个 .cir 文件本身
排查问题靠看电路图看网表（因为错误常在节点名、元件值）

★ 坑 1：Multisim 里你把元件拖上去、连好线就算完了。 LTspice 里你可以完全不画图 —— 直接写网表，然后 Run。 推荐做法：先照着 网表/ 里那四个 .cir 手抄一遍，比对着图形界面点半天学得快。

★ 坑 2：LTspice 的元件没有"引脚号"概念，只有"节点顺序"。 R1 in out 1k 的意思是"R1 接在 in 与 out 之间，阻值 1k"。 第一个节点与第二个节点的顺序有意义（它决定电流正方向），但不影响阻值。

二、元件放置与取值

要做的事MultisimLTspice
放电阻元件库 → Resistor快捷键 R，或网表写 R1 n1 n2 1k
放电容元件库 → Capacitor快捷键 C，或 C1 n1 n2 1uF
放电感元件库 → Inductor快捷键 L，或 L1 n1 n2 1mH
放电压源Sources → DC_POWER快捷键 V（默认是 DC）
放地元件库 → Ground快捷键 G（或网表里用节点 0）
改阻值双击元件 → 改 Value右键元件 → 直接打字，或改网表
给节点命名双击导线 → Net nameEdit > Label Net（快捷键 F4），或网表里直接写名字

★ 坑 3：SPICE 的数值后缀与 Multisim 不同，而且有一个致命陷阱

后缀含义注意
k千（1e3）
meg兆（1e6）★ m 是毫，不是兆！
m毫（1e-3）
u微（1e-6）写 µ 也行，但 u 更保险
n纳（1e-9）
p皮（1e-12）
f飞（1e-15）

★ 这是从 Multisim 迁移时最危险的一个坑： 很多人以为 1m 是"1 兆"，实际是"1 毫"。想写 1MΩ 必须写 1meg。 写错了不报错，只是结果差 1000 倍 —— 而你可能很久才发现。

保险做法：一律用科学计数法，比如 1e6、1e-3。 完全避免后缀歧义。

★ 坑 4：1k 与 1K 一样（SPICE 不分大小写）。 但 1M 和 1m 完全一样 —— 都是毫！所以大写也救不了你，只能用 meg。

三、分析类型对照

Multisim 里的分析对应的 SPICE 指令写法示例
DC Operating Point.op.op
DC Sweep.dc.dc V1 0 20 0.5（V1 从 0 扫到 20，步长 0.5）
AC Analysis（频率响应）.ac.ac dec 100 1 100k
Transient Analysis.tran.tran 5m
Parameter Sweep.step.step param R 1k 10k 1k
自动测量（无直接对应）.meas.meas TRAN vmax MAX V(out)

.ac 的三种扫描方式：

写法含义什么时候用
.ac dec 100 1 100k每十倍频 100 点波特图的标准选择
.ac oct 10 1 100k每倍频 10 点需要更密的低频段时
.ac lin 1000 1 1k线性 1000 点通带很窄、想看清细节时

★ 坑 5：.ac 与 .tran 是两件不同的事 Multisim 的"AC Analysis"给的不是波形，而是频率响应。 LTspice 里也是 —— .ac 必须先在工作点线性化。 所以要"看波形"必须用 .tran，"看频响"必须用 .ac。 不能混。

★ 坑 6：SPICE 里多个分析可以同时写在一份网表里 比如例 2 里同时有 .op、.ac、.tran。 LTspice 会依次全部跑完，然后在波形窗口里给你多个页签切换。 这和 Multisim"一次只能选一个分析"的习惯不同 —— 好处是一次改动能看全部结果。

四、仿真设置（这是迁移中最容易出错的一块）

项目MultisimLTspice
瞬态时长在分析对话框里填.tran <时长>，如 .tran 5m
最大步长"Maximum time step".tran 0 5m 0 1u ← 最后一个参数
起始时间"Start time".tran 0 5m 1m ← 第三个参数
相对误差容限一般不动options reltol=1e-4（默认 1e-3）
初始条件可设节点初值.ic V(out)=0 或元件上加 ic=

★ 坑 7：.tran 的参数顺序极易记错

.tran  Tstep  Tstop  Tstart  Tmax
        ↑      ↑       ↑      ↑
      打印步长  总时长  起始时间 最大步长
  • 只写一个数：.tran 5m → 已够用
  • 要控制精度：.tran 0 5m 0 1u → 最大步长 1µs
  • 最大步长太大会产生假的锯齿/振荡 —— 而那不是电路现象，是数值误差

判断办法：把最大步长改小 10 倍重跑。如果波形变了，说明之前是数值问题。

★ 坑 8：边沿时间不能写 0 PULSE(0 1 0 0 0 5m 10m) 会让 SPICE 无法确定时间步长，可能报错或算出怪波形。 至少给 1n 或 1u。 Multisim 的方波源有默认边沿，SPICE 的 PULSE 没有。

★ 坑 9：PULSE 的七参数顺序

PULSE( V1  V2  Tdelay  Trise  Tfall  Ton  Tperiod )
  • Ton 是高电平持续时间，不是占空比
  • 要 50% 占空比 → Ton = Tperiod / 2
  • SINE 是 SINE(Offset Amplitude Freq Tdelay Theta Phase)

五、看结果：这是 LTspice 比 Multisim 强的地方

要做的事MultisimLTspice
看数字结果分析结果窗口View > SPICE Error Log（.op 和 .meas 都在这）
看波形图形窗口点击图上节点，或 Plot Settings
看波特图自动给要手动改轴（见坑 10）
量两点间放游标右键波形 → Cursor
自动测量无直接对应.meas（见下）
导出数据Export波形窗口 File > Export data as text

★ 坑 10：LTspice 默认不给你 dB，要自己说一次

Multisim 的 AC Analysis 直接画波特图（dB 与相位）。 LTspice 默认画的是 V(out) 的绝对值（单位 V），不是 dB。

改法（两种）：

  1. 直接换轴：波形窗口里 右键纵轴 → View > Decibel（或右键波形曲线）
  2. 改表达式（推荐）：画 V(out)/V(in) 得到传递函数，再换成 dB
在波形窗口顶部有个表达式框，把它改成：
    V(out)/V(in)
然后用右键把纵轴设成 Decibel

★ 坑 11：想同时看幅度和相位，需要两个绘图窗格 Plot Settings > Add Plot Pane，然后在新窗格里画 phase(V(out)/V(in))。 这个操作在 Multisim 里是自动的，在 LTspice 里要做一次，但做完就顺手了。

六、.meas：最值得迁移过来的一个习惯

Multisim 里你是"用眼睛读游标"。LTspice 的 .meas 让你把读数写成指令，结果打进日志。

要测什么写法
稳态值.meas TRAN vfinal FIND V(out) AT 5m
最大值.meas TRAN vmax MAX V(out)
上升时间.meas TRAN tr TRIG V(out) VAL=0.1 RISE=1 TARG V(out) VAL=0.9 RISE=1
某时刻的值.meas TRAN t63 WHEN V(out)=0.264 RISE=2
平均值.meas TRAN vavg AVG V(out) FROM 1m TO 5m
频响峰值.meas AC vpeak MAX mag(V(out))
带宽（−3dB 频率）.meas AC fc WHEN mag(V(out))=0.7071

为什么这值得迁移：

改一个元件值，重跑，数值直接对比 —— 而不是"眼睛看一下，感觉差不多"。 这和你项目里 动手实验/ 的传统是同一件事：把观察变成可复现的测量。

七、绘图习惯的差别

MultisimLTspice
连线拖动快捷键 F3（画线）· F2（放元件）
删除DeleteF5（剪刀）· 或 Ctrl+X
复制Ctrl+C/VF6（复制）· F7（移动）

撤销Ctrl+ZF9
保存Ctrl+SCtrl+S（.asc 是原理图，.cir 是网表）

★ 坑 12：.asc 与 .cir 是两种文件，可以互转

  • .cir = 网表（纯文本，你手写的就是这个）
  • .asc = 原理图（LTspice 自己画的，能双击改参数）

打开 .cir 后，LTspice 会自动画出原理图（View > SPICE Netlist 反过来看网表）。 所以可以先用文本建电路，再看图形 —— 这个顺序对迁移特别有用。

八、一个"迁移检查清单"

从 Multisim 转到 LTspice，按这个顺序做一遍就不会乱：

  • [ ] 数值带后缀的全部改用科学计数法（避免 m/meg 陷阱）
  • [ ] 每个节点起有意义的名字（out 而不是 n001）
  • [ ] 先跑 .op 确认工作点合理，再跑别的分析
  • [ ] .tran 起步用小一点的最大步长，然后放大验证波形没变
  • [ ] .ac 之后手动把纵轴换成 dB
  • [ ] 关键读数写成 .meas，而不是用眼睛读游标
  • [ ] 跑完和"答案卡"对一遍（能力01_..._验证.py 的输出）

九、性能与规模（LTspice 的真正优势）

项目MultisimLTspice
开关电源仿真慢、常不收敛快很多（它是为这个设计的）
节点数上限授权限制无限制
收敛算法一般有专门的收敛选项（.options）
厂商模型库有极全（ADI 自己的器件都在里面）

所以迁移的真正理由不只是"免费"，而是： LTspice 在开关电源、模拟 IC 这类"难收敛"的仿真上，比 Multisim 强一个档次 —— 而这正是工程实际会用到的。
