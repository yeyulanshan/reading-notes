故障排查表：仿真结果不对时怎么查

这份表的用法：你跑出来的结果和 能力01_..._验证.py 给的"答案卡"不一致时， 按从上到下的顺序查。顺序很重要 —— 先查最可能的，不要乱试。

核心原则（和 07_技术/动手实验/助人手册 同一条纪律）：

先确认"你测的是什么"，再看"数值对不对"。 很多"仿真错了"其实是"看错了量"。

一、诊断顺序（按这个顺序查，别跳）

步查什么为什么先查这个
1你看的是不是正确的量？比如你把 V(out) 看成了 V(in)，或把电流看成了电压
2数值后缀有没有写错？1m 是毫不是兆（见下 F1）。这一类错误不报错，只错 1000 倍
3节点连对了没有？网表里的节点名打错会静默地改变电路拓扑
4工作点合理吗？先看 .op。工作点错了，.ac 一定错
5仿真设置对不对？步长、时长、扫描范围
6最后才怀疑：电路理解有没有偏差到这一步才是"要补的知识"

二、12 个具体故障

F1 · 结果差了 1000 倍或 100 万倍 ★最常见

症状：截止频率差 1000 倍、电流差 1000 倍、谐振频率差一大截。

原因：SPICE 的后缀与你直觉不符。

你以为实际含义应该写
1m = 1 兆1 毫（1e-3）1meg 或 1e6
1M = 1 兆也是 1 毫（SPICE 不分大小写）1meg 或 1e6
1u = 1 单位1 微（1e-6）对

排查：把所有带后缀的值改成科学计数法重跑。 如果结果对了，就是这个原因。

预防：一律用 1e6 这种写法，完全避开后缀歧义。

F2 · 波形是假的锯齿 / 高频毛刺 ★常见

症状：本该平滑的曲线出现细密锯齿，或叠了一层高频振荡。

原因：.tran 的最大步长太大，或波形本身不连续但没给边沿时间。

排查：

把 .tran 5m  改成  .tran 0 5m 0 1u

（最后那个 1u 是最大步长）

判断标准：如果改小步长之后波形变了，说明之前是数值误差，不是电路现象。

★ 这条特别重要，因为假的振荡看起来非常像"真的振荡"。 尤其对 RLC 电路 —— 你可能会以为那是谐振，其实是数值噪声。

F3 · 边沿出现无限陡的跳变 / 报"时间步长过小"

症状：PULSE 源驱动时仿真极慢或报错。

原因：Trise 或 Tfall 写了 0。

修改：至少写 1n。

错误：PULSE(0 1 0 0 0 5m 10m)
正确：PULSE(0 1 0 1n 1n 5m 10m)

★ 为什么 Multisim 不报这个错：它的方波源有默认边沿时间。 而 SPICE 的 PULSE 没有默认值 —— 这是迁移时最常见的错之一。

F4 · .ac 的结果完全不靠谱

症状：频率响应形状怪异，或低频段就大幅衰减。

原因：直流工作点不对。.ac 是在工作点附近线性化的，工作点错了它就没意义。

排查：先单独跑 .op，看各节点电压是否合理。 比如 RC 低通里，如果电容没有直流路径（比如悬空），工作点就是未定义的。

修改：确认每个节点都有到地的直流路径。

F5 · .op 报 "singular matrix"（矩阵奇异）

症状：报错 Singular matrix 或 No DC path to ground。

原因：某个节点没有直流通路。典型情形：

  • 两个电容串在一起，中间那个节点
  • 一个节点只连着电容
  • 电流源串在一条没有其他通路的支路上

排查：找出哪个节点没通路。LTspice 通常会告诉你节点名。

修改：加一个大电阻到地。这不是作弊 —— 现实里永远有漏电流。

Rleak thatnode 0 1G

F6 · .ac 跑出来的幅度是"V"不是"dB"

症状：纵轴显示 0.707 而不是 −3，或者显示 5 而不是 14。

原因：这不是错误 —— LTspice 默认画绝对值，不画 dB。

修改（两种）：

  1. 波形窗口里右键纵轴 → View > Decibel
  2. 把表达式改成 V(out)/V(in)（得到传递函数），再换成 dB

★ 记住：Multisim 自动给 dB，LTspice 要你说一次。

F7 · 相位曲线画不出来

症状：想同时看幅度和相位，但只有一个窗格。

修改：Plot Settings > Add Plot Pane（或右键波形区 → Add Plot Pane）， 然后在新窗格里画 phase(V(out)/V(in))。

F8 · 电流符号是负的，以为算错了

症状：I(V1) = -5mA，而手算得 +5mA。

原因：这不是错误。SPICE 的约定是：

电流从元件的第 1 个节点流向第 2 个节点时为正。

V1 in 0 的第 1 个节点是 in；而电源内部电流方向是 0 → in，所以是负。

判断办法：

  • 电源供出功率 → 电流显示为负
  • 电源吸收功率（被充电）→ 显示为正

修改（如果你真的想读正数）：把源写成 V1 0 in -10（两节点对调，电压也变号）。 但更推荐：不改电路，改自己的读法。 因为符号只反映参考方向。

F9 · 元件值明明对了，但结果完全不同

症状：反复检查元件值都没错，但结果就是不对。

原因：节点名打错了。比如把 R2 out 0 1k 写成了 R2 out in 1k。

为什么危险：它不报错，只是电路拓扑变了。

排查：把网表打印出来，逐个节点核对连接关系。 建议画一张纸上的电路图，和网表对照。

★ 这条最能说明"为什么网表是第一公民" —— 看图形界面时你会以为连对了，看文本时错误一目了然。

F10 · 谐振频率偏高/偏低

症状：RLC 电路的谐振峰位置与 f0 = 1/(2π√LC) 算出的不一致。

原因（按概率）：

  1. L 或 C 的后缀写错（见 F1）
  2. 输出取错了位置：取"电感电压"和"电容电压"的谐振频率不同
  3. R 太大：Q 值太低，峰不明显，你会读错位置

排查：

  • 先用 能力01_网表自检.py 确认元件值被正确解析
  • 确认你画的是 V(out)（电容电压）
  • 用 .meas AC fpeak WHEN mag(V(out))=max 自动找峰，别用眼睛

F11 · 阶跃响应看不到超调

症状：RLC 电路的阶跃响应应该是欠阻尼（有超调），但看起来是单调上升。

原因（按概率）：

  1. .tran 时长太短，还没到峰值（本例峰值在 100µs 处）
  2. 最大步长太大，把超调"抹平"了（见 F2）
  3. 输出取错位置：取"电容电压"有超调；取"电阻电压"形状不同
  4. R 太大，实际已经过阻尼

排查：先算 ζ = (R/2)·√(C/L)。ζ < 1 才有超调。 本例 ζ = 0.158，肯定有超调。然后检查 .tran 设置。

F12 · .meas 报错或没输出

症状：写了 .meas 但 SPICE Error Log 里没有结果，或报 Measurement failed。

原因（按概率）：

  1. TRIG/TARG 的 VAL 在仿真范围内没被达到 —— 比如想让信号达到 5V，但它最高只到 1V
  2. RISE=n 的 n 太大 —— 仿真里信号只上升了 1 次，你写了 RISE=2
  3. .meas 引用了不存在的节点名
  4. .meas 的类型不匹配 —— TRAN 测量写在只有 .ac 的仿真里

排查：

  • 先把波形画出来，用眼睛确认那个值确实被达到过
  • 再用 .meas 测量
  • RISE=n 从 1 开始数，不是 0

三、一类特别的故障：结果对，但你不确定它对

这类最难，因为它不给你任何报错信号。

症状：跑出来了，数字看着合理，但你不知道它是不是真的对。

这是"仿真最危险的地方" —— 算错了却以为对。

唯一的防线是独立验证：

方法怎么做
手算一个特例比如把 C 取成 0（短路）或 ∞（开路），答案应该退化成纯电阻电路
量纲检查1/(2πRC) 的结果必须是"1/秒"（Hz）
极端值检查R → 0 时电流应该 → ∞；R → ∞ 时应该 → 0
用另一个工具算比如本目录的 .py 脚本（sympy/scipy 独立算）
物理直觉功耗不能是负的；无源网络的增益不能大于 1

★ 极限检验最有用。举几个本例的用法：

  • 例 2（RC 低通）：把 C 取极小（如 1p），fc 应该变得极高 → 全频段几乎不衰减
  • 例 3（RLC）：把 R 取很大（如 1k），ζ 应该 > 1 → 超调消失，变成过阻尼
  • 例 4（积分器）：把 R 取极小，τ → 0 → 输出应该几乎等于输入（不再是积分器）

如果某个极限下仿真结果不符合直觉，就找到问题了。

四、一张速查卡

结果不对
  │
  ├─ 差了 1000 / 1e6 倍  →  F1 数值后缀（1m 是毫不是兆）
  │
  ├─ 波形有假锯齿/毛刺    →  F2 最大步长太大
  │
  ├─ 边沿极慢或报错       →  F3 Trise/Tfall 写了 0
  │
  ├─ .ac 形状怪           →  F4 直流工作点不对（先跑 .op）
  │
  ├─ 报 singular matrix   →  F5 节点没有直流通路（加 1G 电阻）
  │
  ├─ 幅度单位是 V 不是 dB →  F6 手动换纵轴（不是错误）
  │
  ├─ 电流是负的           →  F8 符号约定（不是错误）
  │
  ├─ 元件对但结果全错     →  F9 节点名打错（不报错！）
  │
  ├─ 谐振/超调位置不对    →  F10/F11 输出取错位置 或 .tran 设置
  │
  ├─ .meas 无输出         →  F12 先确认值确实被达到过
  │
  └─ 结果对但不确定       →  做极限检验（见第三节）

五、最该记住的三条

  1. 先确认你在看正确的量 —— 很多"仿真错了"是"看错了量"
  2. 数值后缀一律用科学计数法 —— 完全避开 m/meg 陷阱
  3. 算错了却以为对，是仿真最危险的地方 —— 唯一防线是独立算一遍（就是本目录那两个 .py 脚本在做的事）
