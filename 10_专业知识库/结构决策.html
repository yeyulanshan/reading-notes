专业知识库 · 结构决策

这份文档不列书单。它定义的是：这个知识库按什么方式组织、每类知识用什么产出形态、以及为什么。

〇、一个前提修正（决定了整份文档的重心）

发起者的背景：自动控制系统大四。电路实验与项目极多；嵌入式做过 51 与 STM32F10x 系列。

这个信息推翻了我最初的设想。 我原来准备的是"从零讲电路"的书单（Lessons In Electric Circuits 从"什么是静电"讲起）——但那些你做过。 按那个思路做，你会读不下去。

所以缺口不是"缺知识"，而是另外三件不同的事。 这份文档把它们分开，因为它们的补法完全不同。

一、三种缺口，价值与难度完全不同

种类 1 · 过时（你会的，但版本旧了）

特征：知识本身没错，工具与生态变了。

这是投入产出比最高的一类——你已经懂原理，只需要换工具，几天就能迁移。

领域学校/你会的现在业界实际用的（本次实测可达）
电路仿真Multisim / PSpiceLTspice（ADI 官方免费）· KiCad（开源 PCB）· Falstad（浏览器即时仿真）
嵌入式芯片51 · STM32F10x（Cortex-M3）RP2040 · ESP32 · Cortex-M33 · RISC-V 系列
嵌入式工具链Keil / IAR（商业，绑定芯片）PlatformIO · CMake · Zephyr · FreeRTOS
嵌入式语言裸机 C现代 C++（constexpr/模板元编程）· Rust（embedded-hal）
控制系统MATLAB / Simulink（学校授权）Python（python-control）· ROS 2 · Julia

为什么这一类最该先做：

  • 迁移成本低（原理你都懂，只是换工具）
  • 立刻能感受到差别（现代工具链的效率提升是数量级的）
  • 它直接消除"和社会隔了点时间"这个感觉——而这是你说的核心痛点

⚠️ 一个实测发现：STM32 官网返回 567（异常状态），RP2040 官方页 403。这说明大厂官网在这网络环境不稳，但 Zephyr/PlatformIO/ESP32/Wokwi 都可达。所以工具类资源应该优先选开源/社区托管的。

种类 2 · 未知（你完全没碰过的）

特征：不是"旧"，是"没有"。这是拓展知识面的主战场。

领域你没碰过的那一层门槛
半导体器件物理（能带、载流子、MOSFET 的物理）高（需要固体物理）
半导体制造工艺（光刻、刻蚀、薄膜、封装）中（流程性知识，但极难自学）
半导体芯片设计流程（RTL → 综合 → 布局布线 → 流片）高，但本次发现可以真上手（见下）
模电深化模拟 IC 设计（不是搭电路，是设计运放/带隙基准）很高
信号处理数字滤波器设计、自适应滤波中
控制系统现代控制（状态空间、LQR、卡尔曼滤波）中高
嵌入式RTOS 内部机制（调度器、优先级反转、内存管理）中
嵌入式通信协议栈（BLE / LoRa / CAN / TCP-IP on MCU）中

★ 一个意外的好消息（本次实测发现）

"芯片设计"这一层，现在真的可以自己走一遍全流程：

资源可获取性意义
Tiny Tapeout✅ 可达花很少的钱就能把设计真的流片（多项目晶圆）
SkyWater PDK✅ 可达开源 130nm 工艺库
OpenROAD✅ 可达开源 RTL-to-GDSII 全流程
OpenLane✅ 可达上面那个的易用封装
Magic VLSI✅ 可达版图查看/编辑

这是整个知识库最有价值的一块。 因为"半导体"在多数人那里只能停留在读的层面（器件物理的书难、工艺看不到）。 而这条开源链路让"设计 → 验证 → 流片"变成可做的。 它和你项目里 动手实验/ 的传统完全一致，而且比任何仿真都更"实在"。

种类 3 · 深化（你以为懂、其实没到底的）

特征：你知道怎么用，但不知道为什么成立、边界在哪。

这一类的特征：它不会给你新东西，但它会让你已有的东西变得可靠。而它往往是前两类的加速器。

你会的底下那一层
会算电路的传递函数拉普拉斯变换为什么能这样用 · 收敛域 · 稳定性判据的证明
会用运放搭电路负反馈的稳定性 · 相位裕度 · 运放内部为什么会有极点
会写定时器中断中断延迟的构成 · 上下文切换的真实成本 · 优先级反转
会用 PID为什么 PID 够用 · 积分饱和 · 采样率与稳定性的关系
会用 ADC采样定理的严格条件 · 量化噪声的真实分布 · 混叠的实际后果

⚠️ 一个诚实的判断：这一类最容易让人低估，因为"我学过"的感觉会阻止你回头。 但它是唯一能提高"可靠性"的那一类——前两类让你会更多，这一类让你已有的不出错。

二、知识库的结构：以「自动控制」为原点

关键洞察：你的专业背景不是"需要补的起点"，而是整个知识库的组织原点。

自动化系的本职是用反馈让系统按想要的方式动。而你要拓展的这几个方向，在这个原点上的位置非常清楚：

                    ┌─────────────────────────────┐
                    │   信号与系统 / 控制理论       │  ← 你的本职，也是中枢
                    │   （传递函数、反馈、稳定性）   │
                    └──────────┬──────────────────┘
                               │
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
   ┌────▼─────┐          ┌─────▼──────┐        ┌──────▼──────┐
   │ 电路/器件 │          │  嵌入式     │        │ 数字/计算    │
   │ 模电数电  │          │  实时系统   │        │ 信号处理     │
   │ 半导体    │          │  通信协议   │        │ 深度学习     │
   └──────────┘          └────────────┘        └─────────────┘
     "怎么实现"             "怎么跑起来"          "怎么算"

这个结构给出的三条推论：

  1. 信号与系统是你的中枢，不是一门课。 电路里的阻抗是它、控制里的传递函数是它、滤波器设计是它、深度学习里的卷积也是它。 → 值得把它"深化"一遍（种类 3），因为它能同时加速其他所有方向。
  1. 电路与嵌入式是"实现层"。 你已经会做，缺的是现代工具（种类 1）。 → 这两块不该重学，该做"工具迁移"。
  1. 半导体是唯一的"向下深挖"。 从系统 → 电路 → 器件 → 物理，这是一个方向。 → 它也是唯一一个你完全没碰过的层次，所以它值得最多投入。

三、每类知识该用什么产出形态

这是这份文档最重要的一节。 底层 项目的产出全是"说明性"的（读了有收获）。但知识库如果也这样，它就只是另一个书单。

"读懂"和"会做"之间有一条真实的鸿沟——你可以完全理解三极管的小信号模型，同时完全不会设计一个偏置电路。

所以知识库的产出必须包含"做"。分三种形态：

形态 A · 可跑（依托仿真，零硬件成本）

适用：信号与系统、控制、数字信号处理、嵌入式逻辑、深度学习

形态：动手实验/ 那套（已有成熟模板）——代码 + 预期结果 + 实测结果对照

本次实测可达的免费平台：

平台用途特点
Falstad电路仿真浏览器即时，无需安装——适合做"看见就懂"的直觉演示
Wokwi嵌入式仿真在线跑 Arduino/ESP32/RP2040 代码，含示波器/逻辑分析仪
LTspice电路仿真ADI 官方免费，业界实际在用
python-control控制系统纯 Python，可直接进 动手实验/
Think DSP信号处理已下载，每章都有可跑代码

形态 B · 可搭（纸面给全，实物自己搭）

适用：电工、模电、数电的进阶部分、传感器接口

形态：电路图 + 元件清单 + 预期现象 + 故障排查表

关键设计：因为有 10_专业知识库/00_基础教材/ 里的 Lessons In Electric Circuits 第 6 卷（实验卷）， 这一形态可以直接建立在它之上——它是 CC 授权、专门讲实验的书。

形态 C · 可设计（走完整工程流程）

适用：半导体芯片设计、模拟 IC、PCB 设计

形态：从需求 → 设计 → 验证 → 产出物的完整链路

本次实测让这个形态变得可行：

链路工具可获取
PCB 设计KiCad✅
RTL 设计 → 仿真Verilog + Icarus/Verilator待验证
综合 → 布局布线OpenLane / OpenROAD✅
工艺库SkyWater PDK 130nm✅
版图查看Magic VLSI✅
实际流片Tiny Tapeout✅

形态 C 是这个知识库能提供、而普通自学提供不了的东西。 因为"设计一个芯片并让它真的被制造出来"，在几年前还需要几十万美元。

四、优先级：一个按你的背景排的顺序

排这个顺序的依据是"你的起点在哪"，不是"哪个领域更重要"。

P0 · 工具迁移（种类 1）—— 最快见效

为什么先做：你已经有原理，只缺工具。几天就能完成，而且立刻消除"隔了点时间"的感觉。

  • 电路：Multisim/PSpice → LTspice + KiCad
  • 嵌入式：Keil → PlatformIO + CMake；51/F10x → RP2040/ESP32
  • 控制：MATLAB → python-control（不替代 MATLAB，但让你不依赖授权）

P1 · 信号与系统「深化」（种类 3）—— 最高杠杆

为什么排第二：它是中枢。深化它能同时加速电路、控制、DSP、深度学习四个方向。

入口：已下载的 Think DSP（153 页，每章可跑）+ 你自己的控制课教材回头读。

P2 · RTOS 与实时性（种类 2，但和你近）

为什么排第三：你做过裸机 STM32，RTOS 是自然下一步，而且门槛不高。

入口：Zephyr（有完整 PDF 文档）+ FreeRTOS；Wokwi 可在线上手。

P3 · 半导体「制造工艺 + 芯片设计」（种类 2，最远）

为什么排最后但值得最多投入：它是唯一一个完全向下的方向，也是唯一能真流片的。

入口：Tiny Tapeout + SkyWater PDK + OpenLane（全部可达）

⚠️ 但要分两步：

  1. 先做工艺与设计流程的上手（Tiny Tapeout 那条链路）——这个可做
  2. 再补器件物理（能带、载流子、MOSFET 物理）——这个要啃固体物理，是最硬的

P4 · 其他拓展（按兴趣）

数字信号处理进阶 · 现代控制（状态空间/LQR/卡尔曼）· 通信协议栈 · 深度学习产出补完（ISLP / UDL 已下载）

五、必须解决的技术前置（不解决会阻断）

这一条与 09_工具与脚本/README.md 里记的缺口是同一个：项目现在没有公式支持。

问题影响
项目所有 HTML 不用 KaTeX/MathJax，数学只能写 <span class="m">"底层"的书数学少，勉强够用
知识库的数学密度远高于"底层"信号与系统、控制、半导体器件物理全都要公式

三个方案（按成本排序）：

方案成本适合
① 纯 HTML <sub>/<sup> + 预排版零简单公式（$H(s)=1/(RCs+1)$ 这类）
② 本地 KaTeX（约 300 KB，可离线）低推荐：能渲染真正的 LaTeX
③ 公式转图片（matplotlib 渲染 LaTeX）中复杂公式，但不可复制文本

建议：先做 ①，遇到瓶颈再上 ②。这件事应该在 P1（信号与系统）开始前解决。

六、需要你决定的三件事

决策 1 · 实物环节走哪条路？

选项成本价值
A. 只做纸面可搭最低你已有很多实验经验，可能够了
B. 实际搭一套中（买元件/开发板）最高，但你的实验经验已经很多
C. 仿真为主低（零硬件）倾向这个——可复现、零成本、且现代工程本来就在仿真里做

取 C 为主 + A 补充：因为你已经有大量实物经验，实物再来一遍边际收益低；而现代仿真工具（LTspice/KiCad/OpenLane）恰恰是学校没教的——那才是种类 1 的缺口。

决策 2 · 半导体往下挖到哪一层？

层次内容难度建议
① 设计流程RTL → 综合 → 布局布线 → 流片中✅ 做（Tiny Tapeout 可达）
② 器件物理能带、载流子、MOSFET 物理高（需固体物理）⚠️ 你自己决定要不要啃
③ 制造工艺光刻、刻蚀、薄膜、封装中（流程性）用视频+图集，不靠书

决策 3 · 知识库的产出密度

底层 每本书 4-5 份 HTML 产出。知识库如果照这个密度，工作量与"底层"同级——那是个长期项目。

建议：知识库不按"每本书一套产出"，而按 "每个能力一个产出"。 比如"能用 LTspice 做交流扫描并读懂波特图"是一个产出，而不是"读完某本书"。

这是两个项目最根本的差别：底层 的组织单位是书，知识库的组织单位应该是能力。

七、下一步（P0 的具体动作）

建议从这一件事开始，因为它最小、最快、且立刻有用：

做一份「电路仿真工具迁移」产出——把 Multisim/PSpice 的常见操作，对照到 LTspice 上，配一个能跑的实例（比如分压电路的直流扫描 + RC 电路的交流扫描 + 波特图）。

为什么从它开始：

  • 你已经有全部原理知识，所以内容不会重复你学过的
  • 它立刻能跑（LTspice 免费、平台已验证可达）
  • 它是知识库第一个产出，用来试出"能力为单位"的形态是否合适
  • 成本最低——如果这个形态不对，改起来容易

而它需要的技术前置：只有几个公式（分压、RC 传递函数），方案 ① 的纯 HTML 排版就够了——所以不用等公式方案定下来。
